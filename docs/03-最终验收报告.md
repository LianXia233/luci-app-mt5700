## 6. 哪些功能保持 API 兼容

- **LuCI RPC 语义兼容**：命令应答 `{success,data,error}` 逐条独立、前端按发送顺序串行化；
  事件推送类型与字段（raw_data/new_sms/incoming_call/pdcp_data/cellscan/memory_full/urc_data）与原 WS 推送完全一致；
  认证由 rpcd 会话 + UCI `websocket_auth_key`（ucode 代理自动附带）共同保证。
- **伪命令**：`AT+CONNECT?` → `+CONNECT: 0/1`；`AT+SCHED?`/`AT+SCHED=<json>`（DTO 键 snake_case 与 Go 一致）；
  `AT^CELLSCAN=STATE/ABORT/<bands>` 状态机（running/done/aborted/error）一致。
- **PDCP 推送 14 字段**：速率 = rate/1024，字段名与原 Go/前端一致。
- **UCI 键**：全部沿用原 `/etc/config/at-webserver`（`connection_type/network_host/network_port/serial_port/websocket_port/websocket_auth_key/cellscan_timeout/schedule_*/notify_*/wechat_webhook/log_file` 等）。
- **前端解析函数**：`convertRsrp/calculateSignalPercent/hexToIP/parseHCSQ/parseMONSC/parsePDCP/parseCMGL/decodeIncomingPdu/buildLockCommand/buildScanCommand/buildUssdCommand/buildSubmitParts` 等全部按原 TS 移植进 `rpc.js/parse.js/smsEncode.js`。
- **本地缓存键**：`sms_sent_messages_cache`、`savedAtCommands`、`atHost/atPort/at_ws_auth_key` 等沿用。

### 9.2 修复的 Rust 后端缺陷（测试驱动）

1. **空闲期 URC 全部丢弃**：`atclient::handle_line` 仅在 pending 命令存在时上报 URC，
   与 Go（空闲期任何数据都视为主动上报、broadcast=true）语义不一致 → 已修复，
   修复后 incoming_call / new_sms / 信号上报均可用（e2e 覆盖来电与短信两条推送链路）。
2. **广播 panic**：`tokio::sync::RwLock::blocking_read` 在异步任务内调用触发
   “Cannot block the current thread from within a runtime” 崩溃 → 改为 `std::sync::Mutex` 事件队列
   （入队非阻塞、有界 500 条）。
