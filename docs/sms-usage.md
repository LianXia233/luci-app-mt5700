# 短信功能使用文档

面向 MT5700M-CN 模组的 LuCI 插件（`luci-app-mt5700`，包名 `at-webserver`）。本文覆盖**短信中心**与**短信设置**两个页面的全部操作、收发行为的真实语义、通知推送配置、常见提示的处置方式，以及验收清单。

- **页面入口**：LuCI → 移动网络 → 5G 模组管理 → **短信中心**（`/cgi-bin/luci/admin/modem/5g/sms`）/ **短信设置**（`/cgi-bin/luci/admin/modem/5g/sms-settings`）
- **语义基线**：本文的收发语义以两部分为依据 —— ① 模组 AT 手册（章节号在各处注明）；② 同型号模组的厂商固件实现（`controller/modem.lua` + `pdul.lua` + `smssend` + `pdu_decoder` + `sendat`，见附录 B）。凡是「厂商那么干、本插件不这么干」的地方都单独写明原因。
- **数据可信度**：页面上的短信、容量、发送结论全部来自**本次真实的 AT 往返**，插件不缓存任何短信副本；后端读不到就报错，不会把「读不出来」洗成「一条也没有」。
- **想看协议而不是操作**：发送／接收／读取三条链路各自下发哪些 AT、字段怎么编、应答怎么判、超时怎么算，单独写在 **[短信链路协议与命令参考](sms-at-protocol.md)** 里，本文不重复。

> 本文所有命令序列都与代码逐条对齐（`src/rust/src/{sms,pdu,urc,atclient}.rs`、`htdocs/.../sms_center.js`、`root/usr/share/rpcd/ucode/mt5700.uc`）。改动其中任一处，本文要跟着改 —— 文档描述的必须是代码真做的事。

## 一、开始之前：先打开短信功能

短信功能默认可能处于关闭态，此时列表与发送都会失败。按顺序检查两处开关（都在**短信设置**页上半部）：

| 开关 | 实际下发的内容 | 说明 |
|:--|:--|:--|
| **短信功能** | **开启**：`AT+CNMI?`（≠ `2,1,0,2,0` 时重设）→ `AT+CMGF?`/`=0` 按需 → `AT+CEUS?`（已是 1 就跳过后面的射频重启）→ `AT+CEUS=1` → `AT+CFUN=0` → 等 ≥1.1 秒 → `AT+CFUN=1` → 轮询 `AT+CFUN?`/`AT+CEREG?` → `AT^IMSSWITCH=1,0,0` → `AT+CGDCONT=5,…` →（可选）`AT+CSCA="…"` | 界面上的「启用时重启射频」是实话：CEUS 要经一次射频开关才生效 |
| **IMS 短信** | 单条 IMS 开关读写（`get_ims` / `set_ims`） | 只想快速确认 IMS 状态时用这一项，不触碰射频 |

### 关闭短信功能会发生什么（务必先看）

**关闭不是「只关 IMS」。** 后端的关闭路径是四条：

```
AT+CEUS=0 → AT^IMSSWITCH=0,0,0 → AT+CFUN=0 → AT+CMGD=1,4
```

也就是：

- **会关射频**：数据连接中断，恢复要等下一次开启（或由拨号/守护逻辑拉回）；
- **会清空首选存储区（`<mem1>`）里的全部短信**，含未读，且**不可恢复**；
- 顺序上 `IMSSWITCH` 在 `CFUN=0` 之前，是为了让那条 IMS 注销请求还能发出去。

因为代价这么大，界面上关闭这个开关会先弹一次确认框，把两件事都写在里面。

### 失败会怎样

任一步没有回 `OK`，页面会报「步骤「X」失败」。如果失败前射频已经被关过（`AT+CFUN=0` 成功、`AT+CFUN=1` 没执行到），后端会**自动补一次 `AT+CFUN=1` 把射频拉回来**，不会把模组留在无射频状态。回滚本身也会记进步骤列表（`回滚射频`）。

射频重启期间的等待是实打实的：`CFUN=0` 到 `CFUN=1` 之间强制留 1.1 秒以上，之后轮询射频与注册恢复（预算 15 秒）。**期间数据连接会短暂中断**，请勿在业务高峰操作。

## 二、短信中心页

### 2.1 界面构成

- **左侧会话列表**：按联系人聚合，显示号码（或字母型发送方，如运营商签名）、最后一条摘要、时刻。顶部三个筛选页签：**全部 / 未读 / 已发**。
- **右侧时间轴**：聊天式单时间轴，对方在左、自己在右，跨天插日期分隔条。
- **顶部**：`+ 新短信`（新建会话）、**刷新**、**批量删除**，以及存储用量 `存储：已用/总量`（来自 `AT+CPMS?` 的 `<mem1>`）。

### 2.2 发送

1. 点 `+ 新短信` 或直接选中一个已有会话；
2. 在底部输入框写正文，回车即发送（**Shift+Enter 是换行**，不是发送）；
3. 输入框上方实时显示「N 字 · M 段」的分段预估（按 GSM 7bit / UCS2 各自的容量算，仅供提示，最终以模组回执为准）。

号码规则：界面按 **5～19 位数字** 校验（允许输入空格、`-`、`()`、`+`，编码前会先剥掉）。发给大陆手机号可以直接写 `138xxxx0000` 这样的 11 位号码，插件会按厂商实机的口径补国家码并按国际格式编码；**特服短号（`10000`、`10086`）按国内格式原样编码**，实测可通。要发给真正的境外号码，请显式带前导 `+`（例如 `+14155550100`）—— 不带 `+` 的 11 位 `1` 开头号码会被当作大陆手机号。

发送结果分三档，界面对它们的处理**互不相同**，这是设计而非缺陷：

| 结果 | 界面表现 | 为什么 |
|:--|:--|:--|
| **已确认（accepted）** | 「发送成功」/「发送成功（N 段长短信）」 | 模组回了 `+CMGS: <mr>` 或明确的 OK |
| **被拒（rejected）** | 「模组拒绝了这条短信」+ 模组原始原因（`+CMS ERROR: …`） | 网络侧已拒绝，重发只会重复失败 |
| **结果不明（unknown）** | 「发送结果不明：…。请勿重复点击发送。」 | 模组没回话。短信**可能已经发走**，插件绝不自动重发，也不建议人工重试 —— 重复计费的风险比慢一点大得多 |

> 结果不明那一档的提示文案会出现两次「请勿重复点击」：后端给的 `message` 本身以这句话结尾（`第 x/y 段未收到模组确认（…）。短信可能已发走，请勿重复点击；如需确认请稍后刷新发送列表。`），前端又加了一句。读着有点绕，但两层都有它的用处 —— 后端那句会在推送/日志里单独出现，前端那句保证弹窗里一定看得到。

**发出去的短信不会写回 SIM 卡**（厂商实现同理），所以列表里不会因为发送而多出一条「已发」。要留底请在界面上看时间轴，或开启第四节的推送。

### 2.3 长短信

超过单段容量时插件自动分片：GSM 7bit 每段 153 个 septet（单条 160）、UCS2 每段 67 字（单条 70），UDH 用 8 位参考号，最多 255 段。emoji 等非 BMP 字符按 2 个 UCS2 单元计，不会被劈成两半。

接收侧的分段由界面合并展示；若某一段缺失，会显式提示「长短信已合并 N 段（部分缺失）」，而不是静默显示残缺正文。

### 2.4 删除与批量删除

- 单条删除：展开会话后点气泡上的「删除」，会先确认。
- **批量删除：一次最多提交 8 个槽位，分多批跑完。** 删除本身是**一个槽位一句 `AT+CMGD`**（模组不接受槽位列表），后端每批还有 30 秒的执行期预算（`SMS_DELETE_BUDGET`）；勾上百条就必然跑过前端的 42 秒硬超时，被掐断的那一次还会连带打开「后端不可用」的共享熔断。所以前端按 8 个一批提交、批间刷新，每批都在预算之内。
- **按槽位从大到小删**。删掉一条后剩下的槽位号可能前移，升序删到一半，后面的号可能已经指向别条短信；降序时高位先走、低位不受影响。前端拼参数与后端下发都用这个顺序。
- 长短信的全部分段会一起删除（界面上是一条消息，模组里是多个槽位）。
- **序号读不出来的条目不可勾选**（复选框禁用，单条删除会提示「该条不在模组存储中」）。这类条目的槽位号读不出来，宁可不删也不能对着来路不明的序号下发 `AT+CMGD`；而**槽位 0 是合法位置**，会照常删除。

### 2.5 「未读」为什么不能当真

模组手册 9.8.2 / 9.10.2 规定：`AT+CMGL` 或 `AT+CMGR` 一旦读出某条「收到的未读短信」，存储里的状态**当场变成已读**。本插件每次刷新列表都是 `AT+CMGL=4`，所以等结果回到界面时，模组给的未读标志已经没了。

因此页面上的「未读」是一个**会话内估计**：「最后一条是收到的、且本次页面里还没点开过」。刷新页面即重置，不代表 SIM 卡上的真实状态，也不跨设备同步。

同一条规则也适用于推送链路：`+CMTI` 到达后插件会用 `AT+CMGR` 读正文，**这一步同样会把该条翻成已读**。所以「开了推送」与「页面上还是未读」这两件事不可能同时成立 —— 推送不影响的是内容，不是状态。

### 2.6 前台会话（打开页面时发生了什么）

短信中心页会向后端申请一次「前台短信会话」（租约 90 秒，页面每 30 秒续期，离开页面/切到后台即释放）。会话存在期间，后台巡检（信号采集、流量统计、拨号对账等）会**让路给短信操作**，所以你手动刷新或发送时不会被巡检排在后面。这一切自动完成，无需设置。

## 三、短信设置页

| 区块 | 作用 | 备注 |
|:--|:--|:--|
| **IMS 短信** | 单条 `AT^IMSSWITCH?` / `=1,0,0` / `=0,0,0` | 不触碰射频，只想确认 IMS 时用这一项 |
| **短信功能** | 见第一节的两条序列 | 关闭有破坏性（关射频 + 清空短信），界面会先确认 |
| **短信中心号码** | 读取（`AT+CSCA?`）与写入中心号，**写入后立刻回读校验**，回读不一致会明确报错 | 允许「3～20 位数字」，`+` 会被剥掉再下发（`AT+CSCA` 只收数字，带 `+` 模组直接回 `+CME ERROR`）。手册 9.5.3 的字符集另含 `*` 与 `#`，但发送时中心号要编进 PDU 的地址字段，那一栏只放得下数字，所以这里**有意不收** `*`/`#` |
| **存储位置** | 选择短信的读写介质：SIM 卡（SM）或模组 FLASH（ME），下发 `AT+CPMS="X","X","X"` | 手册 8.1.3 只定义这两个区名，其它值不发 |
| **存储用量** | 显示三个区的名称与 `<mem1>` 的已用/总量 | 总量为 0 视为「没读到」而不是「已满」 |
| **清空全部短信** | 逐个存储区执行「切区 → 等 0.5 秒 → `AT+CMGD=1,4`」，**结束后把 `AT+CPMS` 还原成操作前的三个区** | `delflag=4` 只清「首选存储器」，所以必须逐区切；切完不等待就删，删的是上一个区。此操作不可恢复 |
| **旧版本本地缓存** | 统计并清除 localStorage 里遗留的「已发记录」 | 不影响模组里的短信。现在列表全实时，本地不再存副本 |
| **USSD 查询** | 发送 USSD（`AT+CUSD=1,"…",15`）与取消（`AT+CUSD=2`），等待 `+CUSD` 上报 | 用于查话费/流量之类的运营商代码 |

> 本页没有「自动化短信转发」和「容量自清理」这两项 —— 仓库里既没有对应的 UCI 键也没有代码。短信事件的对外推送是**服务配置页**的通知通道（见第四节），存储满了只提示、绝不自动删。

## 四、短信推送通知

短信事件可以实时推送到外部通道（企业微信机器人、QQ 机器人、Webhook 等），配置在**服务配置**页（或直接改 `/etc/config/at-webserver`）：

```sh
uci set at-webserver.config.notify_sms='1'            # 短信推送总开关
uci set at-webserver.config.notify_memory_full='1'    # 短信存储满告警
uci set at-webserver.config.notify_tpl_sms='喵呜～，有新短信到啦！快来看看是谁给你发消息了喵~\n发送者: {sender}\n内容: {content}'
uci set at-webserver.config.notify_tpl_memory='喵呜～短信存储空间已经满啦，请尽快清理一下喵，不然可能收不到新的短信了哦！'
uci commit at-webserver && /etc/init.d/at-webserver restart
```

- **短信与来电始终实时直发**，与定时推送间隔（`notify_timer_interval`，默认 10 分钟）无关。
- 模板占位符：`{sender}`（发送方）、`{content}`（正文）、`{time}`（时刻）、`{kind}`（事件类型）。**自定义过文案的设备不受默认值变更影响** —— 后端只在模板为空时才回落默认文案；想让实机也换成新文案，`uci -q delete at-webserver.config.notify_tpl_sms` 清空即可。
- **测试推送**：服务配置页有「测试短信推送 / 测试来电推送」，它构造与真实事件**同形状**的事件走完整链路（总开关 → 分类开关 → 直发 → 模板 → 通道），收到的文本与真实事件一字不差；号码用掩码、正文带「测试消息」标注。想验证文案与实时性，不必真收一条短信。
- **时间口径**：所有对外时间一律使用本机系统时区（LuCI「系统 → 时间同步 → 时区」写下的 UCI `system.@system[0].timezone`）；系统完全没配时区时默认北京时间（UTC+08:00）。短信正文里的时刻来自短信中心时间戳（TP-SCTS）自带的时区偏移（见协议文档 §3.5）。
- 长短信会等所有分段收齐后再推一条完整内容（推送里带「是否完整」标记）。

## 五、收发行为的真实语义（与厂商实机逐条对齐）

这一节是「为什么界面这样表现」的依据，也是回归测试钉住的口径。

1. **提交形态按证据链降级**：`AT+CMGS` 有三种写法，本插件的顺序是
   `两段式（等 > 提示符）` → `长度 + 字面量 \r + PDU` → `长度 + 真 CR + PDU`。
   之所以从两段式起步：绝大多数固件认标准写法，而它**最安全** —— 拿到回执就停手，
   没拿到提示符也绝不会写第二遍 PDU。这台模组对后两种一次性写法里有一种只回显、
   然后彻底沉默（issue #12），识别出「沉默 = 这种写法不被接受」就立刻换下一种，
   不干等满 40 秒。
   **只有「没拿到 `+CMGS`、没见过 `> ` 提示符、也没有错误码」才算形态不被接受**，这时报文根本没被当成提交，换形不构成重复投递。
   拿到本地 `ERROR`/`+CME ERROR` 且整串里带着 PDU 时，说明它把 PDU 当命令行解析了（没收到正文），补写一次 PDU + Ctrl-Z；`+CMS ERROR` 与超时静默一律不补发。
2. **长度字段只算 TPDU**，不含前面的短信中心字段（手册 9.14.5 与厂商编码器同口径）。
3. **收件人号码归一**：剥掉空格/`-`/`()`；`+` 或 `00` 开头判国际；裸的 11 位 `1` 开头手机号补 `86` 并按 TOA 0x91；12 位以上且已带 `86` 同样按国际；其余按国内 TOA 0x81。特服短号按 0x81 实测可发（`102 → 10000` 返回 `toa:"81"`）。
4. **短信中心号**：厂商一律把 PDU 的中心字段写成 0 长度（用卡里存的 CSCA）；本插件读 `AT+CSCA?` 后**编进 PDU**，这样「在短信设置里改过中心号」当场生效，不靠模组记得它被设成了什么。两种写法都能发出去，本插件的选择更可控。
5. **编码选择**：厂商恒用 UCS2、每段固定 60 字；本插件按 GSM 03.38 自动在 7bit/UCS2 之间挑，并用规范的 160/153 与 70/67 容量 —— 纯 ASCII 更省、更长。**这是有意的差异**，不改。
6. **读即已读**：`AT+CMGL=4` / `AT+CMGR` 会把模组里的「未读」翻成「已读」（9.8.2 / 9.10.2）。所以界面的「未读」只能是会话内估计（见 2.5），推送链路上的 `CMGR` 也会吃掉未读（见 2.5 最后一段）。
7. **槽位从 0 开始**：实机一张存着分段短信的卡，头两条就落在 0 和 1 号位。因此 0 是合法槽位，`AT+CMGD=0` 会照常下发；只有「头行里序号读不出」才是无效条目（表示成 `null`，不可删）。
8. **删除逐槽位、从大到小，且有整批预算**：模组不收槽位列表；降序是为了不让中途的槽位号前移导致删错。整批执行期预算 30 秒，超了就停下并如实报告剩下的没删（`failed` 里带上）。
9. **新短信按上报的区去读**：`+CMTI: "<mem>",<index>` 里的 `<index>` 是**该区**的第几格，而 `AT+CMGR` 作用在当前 `<mem1>` 上。插件先按上报区对齐 `AT+CPMS` 再读，避免读到另一个区的同一格、还把那条标成已读。
10. **发送失败先清串口**：某一段没拿到 `+CMGS` 时，插件先向串口写一个 `ESC`(0x1B) 再继续用端口 —— 模组可能停在「等 PDU」的半开输入态，此时紧跟着的 `AT+CPMS?` 会被当成 PDU 吞掉，一次失败会连带拖死后面的读写。厂商 `smssend` 同一步。ESC 在回读容量**之前**写，顺序有测试钉着。
11. **清空后把 `AT+CPMS` 还回原值**：`<mem1>` 决定之后所有 `list`/`delete`/`CMGR` 落在哪个区，切完不还等于把「清空」变成一次改配置的操作。
12. **容量口径**：已用/总量取 `AT+CPMS?` 的 `<mem1>`（与厂商 `action_smslist` 一致）。存储满事件（`^SMMEMFULL` / `MEMORY FULL` / `+CMS ERROR: 322`）只当**提示**，不当**状态** —— 那个上报只在恰好收满的那一刻来一次，界面与定时推送都会重读 `AT+CPMS?` 来判断真实占用。
13. **空列表与读不出来分开**：`AT+CMGL=4` 的判据是**有没有 `OK`**。没有 `OK`（SIM 未就绪、卡被拔出、串口竞争失败）一律报「读取短信列表失败：…」，不会显示成「一条也没有」。

## 六、常见提示与处置

| 界面提示 | 含义 | 怎么办 |
|:--|:--|:--|
| 等待空闲通道超时（10s）：模组正忙或正在重连，请稍后重试 | 通道被别的短信操作或重连占着 | 稍等再刷新；若长期如此，检查模组是否在反复掉线重连 |
| 短信操作进行中，通道已被占用 30s：… | 一次短信事务超过预期时长 | 不要连点；等这一次跑完再看结果 |
| 读取短信列表失败：+CMS ERROR … | 模组没回 OK（SIM 未就绪、卡被拔出、串口竞争失败） | 先确认 SIM 正常、短信功能已开；再刷新 |
| 切换到 PDU 模式失败 | 模组拒绝了 `AT+CMGF=0` | 记录模组原始应答反馈；这属于固件异常 |
| 该短信刚刚提交过，已忽略重复提交（避免重复计费） | 10 秒窗口内同一号码 + 同一正文已提交 | 这就是想要的保护，不必再点一次 |
| 发送结果不明（…）。短信可能已发走，请勿重复点击 | 模组没给回执 | 到运营商侧确认是否送达，不要盲目重发 |
| 模组拒绝设置短信中心号码 / 模组写入后回读不一致 | SMSC 没写进去或读回来不同 | 核对号码格式（3～20 位数字，不带 `+`）；仍失败则记录应答 |
| 不支持的存储区 …（手册 8.1.3 只定义了 SM=SIM 卡、ME=模组 FLASH） | 固件回了手册没定义的区名 | 读侧仍如实显示，只有真要去切/清那个区时会被拦下 |
| 存储：0/0 或用量条消失 | 这一次没读到 / 没解析出 `AT+CPMS?`（后端日志里会有「回读容量失败：…」并带上模组原始应答） | 再点一次刷新；持续如此请检查卡。**这不代表删除/清空失败** —— 那两步的结论只看各自动作的应答 |
| 该条解析失败：… / 该条不在模组存储中 | 模组给出的 PDU 不合法，或头行序号读不出来 | 条目仍会显示，但**不可删除**；刷新后若仍在可记录原文反馈 |
| 后端不可用 / 请求过于频繁 | 守护进程没在监听，或上一次 RPC 被超时掐断 | 检查 `/etc/init.d/at-webserver status`。**两个熔断窗口不同**：ucode 侧「后端无应答」标记 15 秒，前端「连续失败」熔断 8 秒，都会自动解除 |

## 七、验收清单

**自测（无需硬件）**

- `cd src/rust && cargo test` —— 短信相关用例覆盖：三种提交形态与降级顺序、换形重试的唯一触发条件、不自动重发、分片顺序、号码归一、CMGL 槽位 0 与序号读不出（`None`）、删除降序与槽位 0 不被过滤、ESC 写在下一次复用端口之前、按区读取判定、清空后还原 CPMS、模组无 OK 时不得当成空列表、CEUS 先读后写、CNMI 按参数比较而非字符串包含。
- `tests/mock-modem/run-e2e.sh`（**需 Linux**：脚本用 `fuser` 并写死了工具链路径）走完整链路跑 `sms list` / `delete`（含槽位 0）/ `power` 开与关；`node tests/mock-modem/sms-center-render.js` 测前端行为（含 0 号槽位与不可删条目）。

**真机（需要一张能收发短信的 SIM）**

> 边界：**测试短信只允许向 `10000` 发送内容 `102`**。长短信、编码、分段等场景一律在 mock 模组与单元测试里覆盖，不要为此发别的内容或发给别的号码 —— 真发短信任由谁发都会走运营商计费/送达链路。

1. 短信设置页开「短信功能」→ 观察 `CEUS` 从 0 变 1、射频重启后恢复、`IMS` 打开；成功时显示「已启用」；
2. 读中心号 → 与运营商实际 SMSC 一致；
3. 短信中心页刷新 → 列表出现历史短信、容量条有读数；点开后未读标志消失属正常（见 2.5）；
4. 发 `102` 到 `10000` → 应回「发送成功」；`10000` 的回复应出现在列表里，长回复应被拼成一条；
5. 删一条分段短信 → 全部分段消失、容量读数下降；删槽位 0 的那条应能成功；
6. 关闭短信功能 → 界面先弹确认；确认后**射频会关、当前存储区的短信会被清空**（这就是真实行为）；再开启应能把射频与 IMS 拉回来。

**尚未在真机上确认的项**（改动是照厂商实现补的，效果待实机观察）：三种提交形态里哪一种在真机先成功、ESC 是否真能解除半开的 PDU 输入态、`+CMTI` 跨区上报的实际发生率、`AT+CFUN=0/1` 是否足以让 `CEUS` 生效（手册只说「需开关机」）、`CEUS` 取 1（本插件）还是 0（厂商 WebUI）才是对的。

## 附录 A：一次操作实际下发的 AT

| 操作 | 命令序列（全程独占通道，中间不插别的命令） |
|:--|:--|
| 读列表 | `AT+CPIN?` → `AT+CREG?`（前置体检，各 2s，失败只加提示）→ `AT+CMGF?` →（需要时）`AT+CMGF=0` → `AT+CMGL=4`；容量另发 `AT+CPMS?` |
| 发送 | `AT+CMGF?` →（需要时）`AT+CMGF=0` →（请求未指定中心号时）`AT+CSCA?` → 编码 → 每段一次 `AT+CMGS…`（形态按 §5.1 降级）→（任一段未确认时）写 `ESC` → `AT+CPMS?` |
| 新短信到达 | `+CMTI: "<mem>",<i>` →（区不符时）`AT+CPMS="<mem>","<mem>","<mem>"` → 等 0.5s → `AT+CMGR=<i>` |
| 删除 | 按槽位**降序**逐个 `AT+CMGD=<槽位>`（整批预算 30s）→ `AT+CPMS?` |
| 清空 | `AT+CPMS?` →〔每个存在的区：`AT+CPMS="X","X","X"` → 等 0.5s → `AT+CMGD=1,4`〕→ 还原原 `AT+CPMS` → `AT+CPMS?` |
| 开短信功能 | `AT+CNMI?`（≠`2,1,0,2,0` 时 `AT+CNMI=2,1,0,2,0`）→ `AT+CMGF?`/`=0` 按需 → `AT+CEUS?` →（不是 1 时）`AT+CEUS=1` → `AT+CFUN=0` →（≥1.1s）→ `AT+CFUN=1` → 轮询 `AT+CFUN?`/`AT+CEREG?` → `AT^IMSSWITCH=1,0,0` → `AT+CGDCONT=5,…` →（需要时）`AT+CSCA="…"`；任一步失败且射频已关过则补 `AT+CFUN=1` 回滚 |
| 关短信功能 | `AT+CEUS=0` → `AT^IMSSWITCH=0,0,0` → `AT+CFUN=0` → `AT+CMGD=1,4` |

## 附录 C：用户可感知的等待上限

三层预算必须同向递增（后端 < ucode < 前端），反过来就会「后端还在跑、前端已经掐断」，而掐断那次还会打开共享熔断。

| 动作 | 后端预算 | ucode `SMS_ACTION_TIMEOUT` | 界面上限 `SMS_ACTION_TIMEOUT_MS` |
|:--|:--|:--|:--|
| 发送（整个事务，含多段） | 排队 10s + 总预算 60s（单段上限 40s） | 70s | 72s |
| 读列表 | 排队 10s + `AT+CMGL` 25s | 40s | 42s |
| 删除（每批 ≤8 个槽位） | 排队 10s + 执行期 30s + 回读 2s | 40s | 42s |
| 清空全部 | 排队 10s + 每区（切换 + 0.5s + 删 25s） | 70s | 72s |
| 开/关短信功能 | 含射频重启与恢复轮询，最坏约 64s | 70s | 72s |

> 所有上限都是「先由后端给出明确结论，前端才超时」。
