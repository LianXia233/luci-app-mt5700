## 一、开始之前：先打开短信功能

短信功能默认可能处于关闭状态，此时读取列表与发送短信均会失败。请前往 **短信设置** 页面上半部分检查核心开关：

| 配置开关 | 实际执行的 AT 序列 | 业务说明与注意事项 |
| :--- | :--- | :--- |
| **短信功能总开关** | **开启流程**：`AT+CNMI?`（≠ `2,1,0,2,0` 时重设）→ `AT+CMGF?`/`=0` → `AT+CEUS?`（若已是 1 则跳过射频重启）→ `AT+CEUS=1` → `AT+CFUN=0` → 等待 ≥1.1s → `AT+CFUN=1` → 轮询 `AT+CFUN?`/`AT+CEREG?` → `AT^IMSSWITCH=1,0,0` → `AT+CGDCONT=5,…` →（可选）`AT+CSCA="…"` | 界面提示「启用时重启射频」为客观物理机制：CEUS 寄存器必须经过一次射频开关循环才能生效生效。 |
| **IMS 短信开关** | 单条读取/写入 `AT^IMSSWITCH`（`get_ims` / `set_ims`） | 仅用于快速确认或切换 IMS 状态，不会触碰射频与驻网。 |

### ⚠️ 关闭短信功能的影响（高危须知）

> [!CAUTION]
> **关闭不仅是「停用 IMS」，还具有破坏性与物理断网效应**。后端的完整关闭链路为：
> ```text
> AT+CEUS=0 → AT^IMSSWITCH=0,0,0 → AT+CFUN=0 → AT+CMGD=1,4
> ```
> 1. **射频关闭与断网**：数据网络将彻底断开，恢复需等待重新开启或拨号守护进程拉回；
> 2. **清空全部短信**：首选存储区（`<mem1>`）内的全部短信（**含未读**）将被**永久清空且不可撤回**；
> 3. 为防误触，界面点击关闭时会强制弹出风险确认框。

### 失败自愈与回滚

若开启流程中任一步未返回 `OK`，页面将明确提示具体失败步骤。若失败前射频已被关闭（`AT+CFUN=0` 成功但未恢复），后端将**自动补发 `AT+CFUN=1` 恢复网络射频**，避免设备长时间失联。回滚动作亦会完整记入操作步骤日志。

## 二、短信中心页

### 2.1 界面布局

- **左侧会话抽屉/列表**：按联系人号码自动聚合，展示号码（或运营商字母签名）、最新消息摘要与时间。顶部支持快速标签过滤：**全部 / 未读 / 已发**。
- **右侧单时间轴对话**：采用即时通讯级聊天布局，对方消息靠左、己方消息靠右，跨天时自动插入日期分隔胶囊。
- **顶部工具操作栏**：包含 `+ 新短信`（发起会话）、**刷新**、**批量删除** 以及当前存储状态 `存储：已用/总量`（源自 `AT+CPMS?` 的 `<mem1>` 指标）。

### 2.2 短信发送规范

1. 点击顶部 `+ 新短信` 或从左侧直接选中联系人；
2. 在底部多行输入框输入正文，回车（`Enter`）即刻发送；**换行请使用 `Shift + Enter`**；
3. 输入框上方实时呈现分段预估计数（例如「35 字 · 1 段」），依据 GSM 7bit / UCS2 容量实时推演。

> [!TIP]
> **号码规范**：界面支持 5～19 位号码。发送国内手机号可直接输入 `138xxxx0000`，插件自动补齐 `86` 国家码并按国际格式（TOA `0x91`）编码；**特服短号（如 `10000`、`10086`）强制以国内格式（TOA `0x81`）编码**以保障运营商网关正常路由。境外号码请显式带前导 `+`（如 `+14155550100`）。

#### 发送结果分级判定

| 响应结果 | 界面呈现 | 底层成因与处理原则 |
| :--- | :--- | :--- |
| **已确认 (Accepted)** | 提示「发送成功」或「发送成功（N 段长短信）」 | 模组已返回 `+CMGS: <mr>` 明确回执及 `OK` |
| **已拒绝 (Rejected)** | 提示「模组拒绝了这条短信」+ 原始 `+CMS ERROR: …` | 网络侧或卡侧拒绝，已终止操作，重发亦会失败 |
| **结果不明 (Unknown)** | 提示「发送结果不明：…。请勿重复点击发送」 | 模组超时未响应。短信**可能已发出**，插件严禁自动重试，请避免重复点击以免产生多重扣费 |

> [!NOTE]
> 模组并不会将本地发出的短信写回 SIM 卡存储区，因此模组底层不存在已发记录；本插件在界面时间轴上为您保留发信会话，亦可开启推送服务留底。

### 2.3 长短信分片与聚合

当字符超出单段容量时自动分片：
- **GSM 7bit**：单条 160 字符；多段时扣除 UDH 后每段 153 septet；
- **UCS2 (含中文)**：单条 70 字符；多段时扣除 UDH 后每段 67 字符；
- **Emoji 与生僻字**：非 BMP 字符按 2 个 UCS2 单元计算，绝不截断拆分。
- **接收聚合**：长短信在前端自动拼合显示；若网络侧丢段，界面将显著标记「长短信已合并 N 段（部分缺失）」，拒绝静默遗漏。

### 2.4 删除与批量删除

- **单条删除**：在聊天气泡操作区点击「删除」，经二次确认后下发 `AT+CMGD=<slot>`。
- **批量删除分批控制**：前端强制限制**每批最多提交 8 个槽位**。因模组不支持列表删除，必须逐条下发；分批机制可防止耗时突破 42 秒硬超时进而误触发全局服务熔断。
- **严格降序删除**：物理槽位必须**从大到小按降序删除**。若升序删除，前序槽位释放会导致后续槽位号前移，造成误删；降序删除可保障索引稳定性。
- **0 号槽位合法性**：槽位 0 是合法有效的物理存储位置，支持正常读取与删除。只有当头行解析失败时才标记为不可删（禁用复选框）。

### 2.5 未读状态的真实机制

> [!IMPORTANT]
> 依据 3GPP 规范与模组手册（9.8.2 / 9.10.2），`AT+CMGL` 或 `AT+CMGR` 只要读取了未读短信，**模组会自动且当场将其状态重置为已读**。  
> 因此，界面的「未读」标签属于**会话级状态预估**（「最后一条为接收且本次会话尚未点开」），页面刷新后即重置。同时，开启短信推送时后端执行 `AT+CMGR` 同样会触发硬件翻转已读。

## 三、短信设置页

| 功能板块 | 核心 AT 序列与行为 | 业务价值与使用说明 |
| :--- | :--- | :--- |
| **IMS 短信开关** | `AT^IMSSWITCH?` / `=1,0,0` / `=0,0,0` | 仅切换 IMS 承载状态，不中断蜂窝射频连接 |
| **短信功能开关** | 详见第一节开启与关闭链路 | 一键重构短信射频与协议环境（关闭具有破坏性） |
| **短信中心号码 (SMSC)** | `AT+CSCA?` 读取，`AT+CSCA="…"` 写入并立即回读校验 | 限制 3～20 位纯数字（下发前剥除 `+`）；写入后强制二次查询比对 |
| **短信存储位置** | `AT+CPMS="X","X","X"` | 切换读写存储介质：`SM`（SIM 卡）或 `ME`（模组片上 FLASH） |
| **存储容量监控** | `AT+CPMS?` 轮询 | 显示各区名称及首选区已用/总量，总量为 0 判定为读取异常而非满载 |
| **清空全部短信** | 遍历现有存储区下发 `AT+CMGD=1,4`，**执行完毕后必须还原原始 CPMS 设置** | 彻底清空所有存储介质（不可恢复），清理完成后必须将 `CPMS` 还原以防错位 |
| **USSD 交互终端** | `AT+CUSD=1,"…",15` 发送，`AT+CUSD=2` 取消 | 支持查询运营商实时话费、流量套餐等交互代码 |

## 四、短信推送通知

短信到达时可实时推送到企业微信机器人、QQ 机器人、钉钉或自定义 Webhook，配置位于 **服务配置** 页：

```sh
uci set mt5700d.config.notify_sms='1'            # 启用新短信通知推送
uci set mt5700d.config.notify_memory_full='1'    # 启用短信存储空间告警
uci set mt5700d.config.notify_tpl_sms='【新短信提醒】来自: {sender}\n内容: {content}\n接收时间: {time}'
uci set mt5700d.config.notify_tpl_memory='【告警】5G 模组短信存储区已满，请及时登录后台清理！'
uci commit mt5700d && /etc/init.d/mt5700d restart
```

- ⚡ **即时直发**：短信与来电通知走实时事件通道，**不受定时汇总轮询间隔约束**。
- 🧩 **变量占位符**：支持 `{sender}`（发信方号码）、`{content}`（短信正文）、`{time}`（接收时刻）、`{kind}`（事件类型）。
- 🧪 **零成本仿真测试**：服务配置页提供「测试短信推送」，走完整生产链路但发送模拟安全报文，免发真实短信即可验证通道通畅。
- 🕒 **统一时区**：时间戳对齐路由器系统时区（默认北京时间 UTC+8），正文时刻依据 TP-SCTS 内嵌时区准确换算。

## 五、收发行为的真实语义（与厂商实机逐条对齐）

1. **三段式提交形态降级**：`AT+CMGS` 优先执行标准两段式（等 `>` 提示符）→ 失败则回退至单行字面量 `\r` 模式 → 最后尝试单行真回车。仅在明确无回执且未见提示符时才切换形态，杜绝重复投递。
2. **TPDU 严格长度**：`AT+CMGS=<len>` 中的长度仅计算 TPDU 字节，不计 SMSC 字段。
3. **号码自适应适配**：自动过滤空格与标点，智能判断国内/国际格式，保障特服号正常解析。
4. **显式注入 SMSC**：本插件读取 `AT+CSCA?` 后将其直接编译进 PDU 头部，避免修改短信中心号后模组未同步生效。
5. **字符集动态精简**：ASCII 文本走 GSM 7bit（单条 160 字），包含中文或生僻字时平滑升级至 UCS2（单条 70 字）。
6. **读即已读原则**：严格遵守 3GPP TS 27.005 规范，底层执行 `CMGL` / `CMGR` 必造成硬件已读标记。
7. **槽位从 0 编址**：首条短信存储索引为 0，底层杜绝 `slot > 0` 的错误边界校验。
8. **降序分批删除**：按槽位大到小降序执行，避免槽位前移索引污染；单批 8 槽位限制规避超时。
9. **跨区读取校准**：`+CMTI: "<mem>",<index>` 触发时，若上报存储区与当前 `CPMS` 不符，必须先对齐介质再读单条。
10. **串口清态防阻塞**：发送失败或异常断开后必须先向串口写入 `ESC` (0x1B)，强行终止模组半开输入等待。
11. **清空后介质复原**：执行全盘清理后必须重写原 `CPMS` 变量，避免改写后续读写路径。
12. **存储满事件视作轻量告警**：`^SMMEMFULL` 仅触发一次性通知，不强加未经授权的自动静默删除。
13. **空列表严格区分状态**：没有收到 `OK` 一律视为「链路异常/模组忙」，绝不呈现为「无短信」。

## 六、常见提示与处置

| 界面异常提示 | 根本原因分析 | 建议处置方案 |
| :--- | :--- | :--- |
| **等待空闲通道超时（10s）** | AT 互斥锁被高频重连或长耗时操作独占 | 稍后重试；若频繁出现需检查模组是否反复掉线 |
| **读取短信列表失败：+CMS ERROR** | 模组底层拒绝（SIM 未插好、被锁卡或射频已关闭） | 检查 SIM 卡就绪状态及短信设置中的总开关是否开启 |
| **切换到 PDU 模式失败** | 模组拒绝执行 `AT+CMGF=0` | 记录日志排查，通常需重启模组或重载后端服务 |
| **已忽略重复提交（避免重复计费）** | 10 秒防抖窗口内提交了相同号码与内容 | 正常防误触保护，无需重复点击发送 |
| **发送结果不明：请勿重复点击** | 模组发包后未在规定窗口内回传 `+CMGS:` | 运营商侧可能已处理，请前往运营商后台或稍后刷新确认 |
| **模组写入后回读不一致** | SMSC 中心号码参数未成功固化到 SIM | 检查号码格式是否为 3～20 位纯数字，无需额外添加 `+` |
| **存储容量显示 0/0 或消失** | 瞬时串口竞争导致未能解析到 `AT+CPMS?` | 点击右上角「刷新」重试，不影响既有短信记录 |
| **后端不可用 / 请求过于频繁** | 后端服务未就绪或连续触发熔断保护 | 执行 `/etc/init.d/mt5700d restart` 重启后端进程 |

## 七、验收清单

### 自动化与本地自测（无需模组硬件）
- `cd src/rust && cargo test`：覆盖三种发送形态降级、号码归一化、0 号槽位解析、降序删除、ESC 清态与时区计算全量单测。
- `node tests/mock-modem/sms-center-render.js`：验证前端会话聚合、0 槽位与错误条目安全渲染。

### 实机集成验收（需配备可收发短信的测试 SIM）
> [!WARNING]
> **真实短信发信基线**：测试仅允许向运营商官方服务号 `10000` 发送文本 `102`。绝不允许测试向任意私人号码盲发。

1. **功能启停**：在设置页开启短信功能，验证射频关闭后恢复，状态正常跳转为「已启用」；
2. **中心号回读**：验证 `AT+CSCA` 成功回读且与运营商参数吻合；
3. **列表展现**：短信中心成功加载历史对话，存储容量显示具体数值；
4. **单条收发**：向 `10000` 发送 `102`，验证立即显示发送成功并收到回执短信；
5. **分片删除**：删除长短信，验证多槽位同时被清除且容量计数递减；
6. **高危关闭**：点击关闭短信，确认弹出高危警告，确认后模组射频关停且存储区按规范格式化。

| **关闭短信** | `AT+CEUS=0` → `AT^IMSSWITCH=0,0,0` → `AT+CFUN=0` → `AT+CMGD=1,4` |

| :--- | :--- |
| `/usr/lib/lua/luci/controller/modem.lua` | 旧版 LuCI 控制器，提供 `smslist` / `smssend` / `smsdel` 基础 JSON 接口 |
| `/usr/bin/pdul.lua` | 旧版 PDU 编码脚本，硬编码单段 60 字符，非 ASCII 字符处理粗糙 |
| `/usr/bin/smssend` | 号码预处理并尝试绕过 `sms_tool_q` 的单行发送工具 |
| `/usr/bin/pdu_decoder` | 列表解码器，将长短信按发件人合并，但存在丢弃时区导致时差的已知缺陷 |
| `/usr/bin/sendat` | 基于 Linux 串口的裸探测工具，缺乏事务控制与并发锁机制 |
| `/usr/bin/sms_tool_q` | 依赖 `>` 提示符握手，因 MT5700M 固件不吐 `>` 提示符而在本模组上无法工作 |

### 附录 C：超时预算对照表（递增式防断流）

| 操作链路 | 后端守护进程预算 | ucode 中间层 (`SMS_ACTION_TIMEOUT`) | 前端视图硬超时 (`SMS_ACTION_TIMEOUT_MS`) |
| :--- | :---: | :---: | :---: |
| **发送（含多段拆分）** | 排队 10s + 60s 事务 | 70s | 72s |
| **列表读取** | 排队 10s + 25s 遍历 | 40s | 42s |
| **删除（≤8 槽位/批）** | 排队 10s + 30s 执行 | 40s | 42s |
| **清空全部存储区** | 排队 10s + 逐区等待清理 | 70s | 72s |
| **启停短信功能** | 排队 10s + 射频开关与注册轮询 | 70s | 72s |

> 规范遵循「后端先出确定结论、中间层略宽、前端最后兜底」原则，避免异步链路竞争中断。
