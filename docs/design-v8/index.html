链路 v8
让 12 个页面先说结论

现在的界面把"能读到什么"全铺在页面上：33 项诊断、20 多个读数、11 张卡片，权重一样。 改版只做一件事 —— 按 结论 → 需要你做的事 → 细节 重新排序， 再把"模组 → 拨号 → 网络 → 终端"这条链路做成界面上唯一醒目的骨架。

为什么重做，而不是再换一次皮

设计诊断

这套界面之前已经调过四版配色与间距，但骨架一直是"一列卡片往下堆"。问题不在皮肤，在结构：

症状现在发生的事改版怎么做
没有结论进页面先看到 4 个圆环、6 张卡；"到底能不能上网"要自己拼。首屏一句人类语言：已连接，可以上网，下面才是数字。
读数与操作同权"信号质量"和"断网排查"长得一样，都要滚到才看见。读数降级为细节；需要你处理单独成条，置顶。
链路不可见模组、拨号、注册、客户端分散在 4 张卡里，断一环看不出断在哪。一条 链路条 横贯首屏，四段各带状态灯。
危险操作无预告切卡 / 切 Profile / 锁频保存会断网，点下去才知道。动作旁固定 影响预告条：断多久、影响谁。
看不见 ≠ 不可用能力不满足时控件直接消失，用户以为功能不存在。动作常驻，灰化 + 一句为什么。
说明像实验记录页面里出现日期、手册条数、对照实验的推理。界面只留能做什么 / 不能做什么 / 怎么办，取证过程进 README。
改版边界：不动 Rust 后端、不动 AT 通道、不动 rpcd 方法名；只重排信息层级、重做样式与组件，页面能力一个不少。
01

五条原则

每条都可验收
01

结论先行

每页第一屏必须有一句"现在怎么样"。没有结论的页面不允许只有一个读数网格。

02

一条链路

模组 → 拨号 → 网络 → 终端。四段状态永远同时可见，断点自己会亮。

03

动作常驻

能做的动作一直在，不能做就灰化并写明原因。不让控件凭空消失。

04

危险先告知

会断网、会不可逆的操作，旁边固定一条影响预告，不靠确认框兜底。

05

数字不修饰

读数给裸值（ARFCN 就是 504990），单位小一号；换算只在必须时做，并注明口径。

信息密度怎么排

同一屏里最多三种字号层级，靠位置和留白分层，而不是靠加框加阴影：

层级内容字号 / 字重约束
L0 结论一句话状态 + 主操作25px / 650每页只允许一个
L1 读数4 个以内核心数值21px 等宽 / 600固定格子，不随内容撑开
L2 明细表格、键值、日志12px / 400可折叠，默认不抢视线

网络状态：三个改动，三个理由

P1-1

顶部先给结论

"已连接，可以上网 / 已连接但转发受限 / 未连接" 三种句式覆盖全部状态，右侧四个数字只做佐证。

P1-2

链路条替代四张卡

模组、拨号、网络、终端原本散在"连接状态""SIM 与设备"里；现在一条横带全给，断点在哪一眼可见。

P1-3

需要处理单独成条

只放"影响使用但可继续"的问题；纯读数不进来。没有问题时整条不出现，不占版面。

断网排查：把 33 项变成一条结论

原来的排查卡是"按钮 + 三层折叠 + 明细塞在卡内滚动"。改版把它拆成三块：

  • 结论区：一句话说清"发现了什么、影响谁"，右侧四个计数（通过 / 存疑 / 未通过 / 跳过）。
  • 三层用分段控件切换，每层一个小结；当前层用底色标出通过数，不再整页铺 33 行。
  • 每行四列固定：状态灯 / 项目 / 证据（等宽，可直接对照串口）/ 动作。证据不折叠，因为排查时它就是最有用的东西。
「一键修复」保持灰化。这是用户 2026-09-19 的明确选择 —— 排查只给证据，不自动改。灰化按钮比隐藏按钮诚实：它告诉用户"这里本来有个能力，但我不会替你按下"。

eSIM / 短信 / 语音 / 终端

页面主结构关键约束
eSIMEID 与容量一条横带 → 断网预告 → Profile 表 → 待发回执「当前联网」行的禁用/删除必须灰化并解释原因；待发回执删了不可逆，单独提醒
短信中心三栏式：会话 238px / 对话自适应 / 底部发送区发送前显示编码与将分几条；存储容量常驻左下，不藏在设置页
语音左拨号盘、右状态与记录无音频通道的能力（免提/静音）常驻灰化 + 一句原因，不隐藏
AT 终端深色滚动区 + 固定输入行 + 常用命令 chips写命令醒目区分；说明里明确"不要下发周期上报"

四个宿主约束，改样式前必须知道

约束现象与做法
Argon 给 h1–h6 加强制字重font-weight: normal !important。页面标题、卡片标题的 600/650 必须带 !important，否则全变细体。
Argon 把裸 h2/h3 当卡片画h2 被套白底 + 内边距 + 阴影；h3 还被给了 width:100%。必须显式清掉 background / box-shadow / border-radius / padding，卡片标题再加 width: fit-content。
内容区 1142px12 列栅格按 1142 设计，间距 12–16。别用 100% 撑满的宽表格，横向滚动会毁掉对齐。
宿主已有全局样式所有自有类保留 mt5700- 前缀；按钮不要再挂 cbi-button-*，两套样式会打架。

验收清单

  • 首屏有结论：12 个页面每页第一屏都有一句人话状态，不依赖读者自己拼读数。
  • 链路可见：网络状态页四段链路在 1142px 下不换行、不截断；任一段变色都能被看见。
  • 灰化有原因：所有 disabled 控件旁边都有 ≤ 30 字的理由，没有"凭空消失"的能力。
  • 危险有预告：切卡、切 Profile、锁频保存、升级、恢复出厂，五处都有影响预告条。
  • 对比度达标：正文与读数的文字对比度全部 ≥ 4.5:1（5 个信号色已逐一核对）。
  • 数字不跳：读数等宽 + tabular-nums，刷新时宽度不变。
  • 文案简练：单条中文不超过 100 字，不出现日期、手册条数、对照实验（守卫已存在）。
  • 宿主不被破坏：标题重置四条仍在，font-weight 仍带 !important，卡片标题仍 fit-content。
这一版最容易犯的错：把新组件加在旧骨架上 —— 结论区下面还是 11 张平权卡片，读起来仍是清单。 落地时请按页面整块替换，而不是"顺便美化一下"。
