**修好了「有 IP 却上不了网」** —— 自动创建的模组接口没有登记进防火墙区域，没有 NAT 就出不了网。

### 修复

- **fix(firewall)**: 自动创建的模组接口现在会**登记进承载 NAT 的上行防火墙区域**（`wan`）。
  此前接口只写了 `network` 配置，从未进过任何防火墙区域；而 fw4 只为**区域内的接口**下发源地址转换与 `lan → 上行区域` 的转发放行，接口不在区域内时内网源地址不会被改写，上游无法回程。表现就是：**模组拨号正常、接口也正常拿到 IP（`ifstatus` 有地址、默认路由已建立），但路由器背后与内网都打不开网页**。
  机型定制包预置的接口之所以没事，只是因为它同时把 `MT5700M` / `MT5700Mv6` 写进了 `wan` 区域的 `network` 列表 —— 同一个接口，差的就只有这一处登记。

- **fix(firewall)**: 区域判定不写死索引（区域顺序随固件而异）：优先名为 `wan` 的区域；没有再找带 `masq` 的区域（并优先其中已登记现成上行口的）；都没有则新建一个标准 `wan` 区域，并补建 `lan` 区域与 `lan → wan` 转发。
  **只做登记，不改动既有区域的 `masq` / 转发等既有定义** —— 若目标区域没开 `masq`，只打一条警告，不擅自开启（避免破坏「公网地址直路由」这类刻意配置）。

- **fix(firewall)**: 接口在 `ensure_interfaces`（安装/升级）、`on_uplink`（后端确认拨号就绪）、`ensure_modem_interface`（开机启动）三条路径上都会核对区域登记，**且不只在「新建接口」分支执行** —— 存量设备接口早已存在，只在新建分支做登记正好会漏掉它们。可重复执行，无改动时不会提交也不会重载防火墙。

### 实机验证（Hiveton H5000M / ImmortalWrt SNAPSHOT / fw4）

| 状态 | `nft` srcnat 跳转 | 以 LAN 地址为源 ping 223.5.5.5 |
|:--|:--|:--|
| 接口不在区域内（故障态） | 跳转不含模组网口 `eth2` | **100% 丢包** |
| 执行 `ensure_interfaces` 后 | `oifname { "eth1", "eth2" } jump srcnat_wan` | **0% 丢包（~26ms）** |

日志实测：

```
已将 MT5700M 登记到防火墙区域 wan（此前不在区域内，会导致有 IP 却无法上网）
已将 MT5700Mv6 登记到防火墙区域 wan
防火墙已重载（模组接口的区域登记已生效）
```

### 已经卡在这个状态的设备怎么修

不用重装，执行一次即可（幂等，可重复执行）：

```sh
/etc/init.d/at-webserver ensure_interfaces
```

完成后用 `/etc/init.d/firewall status` 或刷新 LuCI「网络 → 接口」确认。若仍不通，按 README 的排查表逐项核对（区域登记 → NAT 规则 → 数据面 `AT^NDISSTATQRY?`）。
