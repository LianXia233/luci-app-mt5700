### 🎯 问题背景与根因定位

| 项目 | 详情说明 |
| :--- | :--- |
| **故障表现** | 普通模式下各页面顶部英雄栏右上角的看板娘头像不显示，`.mt5700-hero-art` 容器宽度始终为 `0px` |
| **影响范围** | 12 个视图页面的英雄栏看板娘占位 |
| **根本原因** | `Mt5700.page()` 构建视图 DOM 时，节点尚未被 LuCI 挂载至 `document`；而 `syncMascots()` 检索范围固定为全局 `document.querySelectorAll('.mt5700-hero-art')`，导致挂载前无法发现当前页面内的头像容器，头像未能成功注入。该缺陷自 v1.32.5 引入统一模式钩子时即已存在。 |

```diff
- // 缺陷：在页面挂载前查询 document 拿不到当前视图节点
- document.querySelectorAll('.mt5700-hero-art')
+ // 修复：支持传入当前节点作用域 root，挂载前即可完成预渲染
+ (root || document).querySelectorAll('.mt5700-hero-art')
```

### 🛠️ 核心修复方案

- 🧩 **支持作用域传递**：`syncMascots(root)` 重构为支持显式传入根节点作用域，缺省自动安全回退至全局 `document`。
- ⚡ **生命周期前置**：在 `Mt5700.page()` 内部构建时直接触发 `syncMascots(node)`，在页面交由 LuCI 挂载前即注入头像，彻底消除渲染时序盲区。
- 🔄 **双模式平滑兼容**：极简模式（MD3）切换依旧复用 `bindMode()` 驱动全局 `syncMascots()`，生命周期平滑无冲突。
- 🛡️ **自动化防回归门禁**：新增 `tests/mascot-render-test.js` 回归测试，对作用域、DOM 结构与资源版本戳形成强断言保护。
