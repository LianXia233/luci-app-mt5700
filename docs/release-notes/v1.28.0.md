# v1.28.0

**主题**：推送文案统一前缀与排版重做、QQ 推送富文本化（独立 `qqpush` 模块）、QQ 目标 ID 与绑定进度的交互优化。三件事来自同一类诉求 —— 推送是用户每天在 QQ 里直接看到的东西，它的**前缀、排版、富媒体能力**与**配置过程的清晰度**都应该是产品级而非"能跑就行"。

---

## 1. 前缀统一：所有推送只带 `{time} {count}`

改动前每条推送自带一套装饰前缀：短信是"喵呜～，有新短信到啦！快来看看是谁给你发消息了喵~"，来电是"喵呜～有电话打进来啦…"，存储满又是另一句。前缀（`notify_tpl_prefix`）与模板内前缀两套并存，用户改前缀时模板里的句子纹丝不动。

v1.28.0 起：

- **全局前缀默认值固定为 `{time} {count}`**（事件时刻 + 本条消息条数），留空时才不添加；
- **各事件模板不再自带任何装饰性前缀**，默认值首行即标题（如 `新短信` / `来电` / `短信存储空间已满`），其余为 `键：值` 行；
- 默认模板一览：

| 模板 | 新默认值 |
|:--|:--|
| 前缀 | `{time} {count}` |
| 新短信 | `新短信` / `发送者：{sender}` / `内容：{content}` |
| 来电 | `来电` / `{content}` |
| 信号变化 | `{content}`（正文由后端组装） |
| 存储满 | `短信存储空间已满` / `后果：清理前可能收不到新短信` |
| 批量汇总 | `批量通知汇总`（合并窗口已移除，仅兼容保留） |

## 2. 文案重做：信号巡检 / 网络切换提醒 / 定时状态

三类正文生成器全部重排，原则一致：**去 emoji、统一全角冒号、`键：值` 成行**（全角冒号是 QQ Markdown 渲染的锚点，见下节）：

- **信号巡检**（`signalwatch`）：标题 `5G 信号巡检` / `4G 信号巡检`，随后时间、频段（`n41 · 2565 MHz / 100 MHz`）、网络能力总评，空行后四行指标对照（RSRP / RSRQ / SINR / SIGNAL，基准值 + 实测 + 结论）；
- **网络切换提醒**（`urc`）：制式切换时标题为 `网络切换提醒`，否则 `信号变动通知`；时间 / 制式 / 信号三行键值，随后指标行与"小区信息"分段（频点 / PCI / TAC / 小区ID）；
- **定时锁频切换**（`schedule`）：`定时锁频切换` 标题 + 时间 / 模式 / LTE / NR / 执行操作 / 切换次数 / 结果七行键值；
- **定时状态快照**（`timerpush`）：`当前状态（定时推送）` 标题，信号行改为 `信号：5G · n41 · …`，存储行改为 `短信存储：3 / 50`，无读数时明说"暂无读数"。

旧文案里的 `📶 🕒 💾 🔄 ⚡ 📡` 全部移除（用户明确要求全文不用 Emoji），半角冒号统一为全角。

## 3. QQ 推送富文本化：独立模块 `qqpush`

### 3.1 为什么拆模块

v1.27.0 之前 QQ 通道的鉴权、发消息、错误码处理全部混在 `notify.rs`（1510 行）里，通知中枢与平台细节互相纠缠。本次把所有 QQ 机器人能力（官方 OpenAPI v2）收敛到独立模块 `src/rust/src/qqpush.rs`，`notify.rs` 只保留"事件 → 模板 → 多通道投递"的中枢职责。两侧边界：

- **notify**：产出**纯文本正文**（标题 + `键：值` 行）与全局前缀，不关心对端格式；
- **qqpush**：把正文组装成 QQ 支持的消息形态并投递，负责格式选择与降级。

### 3.2 消息形态（依据官方「消息类型总览」）

发送侧 `msg_type`：`0` 纯文本 / `2` Markdown / `7` 富媒体。单聊场景**不能发送 ark 结构化卡片**，因此富媒体化走 Markdown 路线：

- **Markdown（msg_type=2，默认）**：单聊/群聊自定义 Markdown 自 2026-04 起对所有机器人开放，无需模板申请。组装规则（`qqpush::build_markdown`）：
  - 正文首行 → `## 二级标题`（若首行本身是 `键：值` 行则不硬造标题）；
  - 全局前缀 → `> 引用行`（保留时间与条数信息又不抢标题）；
  - `键：值` 行 → `- **键**：值` 列表项（全角冒号优先，兼容旧配置的半角写法；URL 行不拆）；
  - 空行保留分段，其余行原样。
- **纯文本（msg_type=0）**：兜底形态。
- **内嵌键盘（`keyboard.content.rows`）**：可附在 Markdown 消息上，默认带一枚「打开管理页」跳转按钮（地址取 `qq_keyboard_url`，留空按 `network.lan.ipaddr` 推导）。
- **自定义菜单（`PUT /v2/menu`）**：C2C 单聊窗口底部菜单，默认两项「查询状态 / 查询流量」（`send_message` 类型，点击后指令填入输入框）。启动时自动配置一次（`qq_menu_enabled=1`），也可用 LuCI「配置 QQ 菜单」按钮或 `qq_menu` RPC 手动触发。

### 3.3 降级阶梯（可靠性优先）

富文本不是单点故障：

1. Markdown + 键盘 → 失败（如键盘形状不被接受）→ **去掉键盘重发**（富文本本身仍要送达）；
2. 仍失败且格式为 `auto` → **回落纯文本**，并进入 10 分钟冷却（期间直接发纯文本，避免每条都先撞一次墙）；
3. 格式为 `markdown`（用户显式选择）→ 不回落，让错误暴露。

### 3.4 已知限制

- 本模块只做**主动消息**推送，不连 WebSocket 网关：拿不到 `msg_id`/`event_id`，也收不到用户消息与按钮回调。因此自定义菜单里的指令项点击后仅把指令填入输入框，**机器人应答指令需要长连接指令处理（规划中）**；「打开管理页」跳转按钮不受此限制。
- 自定义菜单的 `link` 项官方要求 `https://` 开头，而 LuCI 管理页在局域网是 `http`，故默认菜单不使用 link 项。
- QQ 主动消息频控不变：单关系 20 条/分钟、每个好友每天最多 1000 条。

## 4. 前端交互：目标 ID 提示与绑定进度

- **QQ 推送目标 ID**：提示重写 —— 说清 openid 是平台分配的联系人标识、不是 QQ 号也无法换算，绑定模式留空即可、手动模式该粘贴什么；
- **绑定进度**：新增 600 秒监听窗口的**进度条**（仅 waiting 状态显示，其余状态整条隐藏，避免"没在绑定也挂着空进度"），剩余时间改为 `m:ss / 10:00` 秒表格式；
- **新增控件**：QQ 消息格式（自动 / 富文本 / 纯文本）、富文本「打开管理页」按钮开关与跳转地址、启动时自动配置菜单开关、「配置 QQ 菜单」按钮（即时生效，不等重启）。
