**v1.14.13 为稳定性与兼容性版**：修复 AT 口判定被接口名误命中的真实缺陷，新增 `/dev/serial/by-id` 稳定设备路径支持，并为「无模组 / 模组未就绪 / 同型号撞名」三类场景补齐多级兜底。**未触碰任何 IMEI 相关代码与数据流**，未引入新的外部依赖。

### 一、修复 AT 口判定误命中（核心）

原实现用 `iface.contains("AT")` 寻找 AT 口。实机接口名由模组固件写死为：

```
TDTECH Connect - PC UI Interface       <- 真正的 AT 命令口
TDTECH Connect - Application Interface <- 应用/数据口
```

由此产生两处反向误判：

1. `PC UI` 中间有空格 → `contains("PCUI")` **不命中**；
2. `Applic**at**ion` 含子串 `at` → `contains("AT")` **误命中**。

后果是 Application 口被打成 1 分（「模组/命令口」）、真正的 PC UI 口反而落到 2 分（「未知」），排序把 **Application 排在 PC UI 之前**：

| 候选 | 修正前得分 | 修正后得分 |
|:--|:--:|:--:|
| `/dev/serial/by-id/...-if13-...`（Application） | **1**（抢首位） | 2 |
| `/dev/serial/by-id/...-if12-...`（PC UI） | 2 | **0**（首选） |

功能上此前之所以未暴露，是因为探测阶段会逐个真发 `AT`：Application 口通常不应答，需**白等一个 800ms 超时**才轮到 PC UI 口；但若某些固件的 Application 口恰好回了 `OK`，就会直接把错口选成 AT 口。

**修复方式**：改为按非字母数字切 **token 后整词匹配**（`AT` 必须是独立词），并新增回归用例 `pcui_must_outrank_application` 守护该行为。实机验证：候选序首位由 `if13` 纠正为 `if12`，探测**首次即命中**——日志中零「无有效应答」跳过记录。

### 二、新增 `bInterfaceProtocol` 二级兜底

接口名字符串缺失（部分 OEM 固件留空）或无法识别时，回退读 USB 接口描述符：

| 协议号 | 接口角色 | 判定分 |
|:--|:--|:--:|
| `0x12` | PC UI / AT 命令口 | 0 |
| `0x14` | GPS（只吐 NMEA，明确排除） | 3 |
| `0x13` | Application Interface | 2 |
| `0x1b` / `0x1c` | SerialB / SerialC | 2 |

该值写死在模组固件中，**换 USB 口、换 xHCI 控制器、换主机均不变**，比接口名字符串更耐固件改版。

### 三、强弱信号分级与协议号交叉校验

若多个口同时命中 AT 判据（如某 OEM 把数据口也描述成 `AT Port`），排序会退化为字典序、选谁纯属巧合。现分级处理：

- **强信号**（`PCUI` / `PC UI` / `ATPORT`，专有叫法）→ 直接采信，不受协议号干预；
- **弱信号**（`AT` / `Modem` / `Command`，通用词）→ 允许被协议号 `0x13/0x14/0x1b/0x1c` 否决。

既避免伪 AT 口抢位，又避免「名字明明是 PCUI 却被非常规协议号压走」的反向误判。

### 四、`/dev/serial/by-id` 稳定路径支持

**背景**：`ttyUSB*` 编号由内核枚举顺序决定，同一模组换 USB 口或换控制器后会整体平移（实测换口后 PC UI 从 `ttyUSB1` 变成 `ttyUSB2`），用户手工选定的路径随即失效，表现为「昨天配好能用，拔插一次就再也不通」。

**探测顺序改为三层**：① `by-id` 稳定链接（优先，编号漂移免疫）→ ② `ttyUSB*`/`ttyACM*`/`ttyAP*`（回退）→ ③ `ttyS*`/`ttyAMA*`（仅在完全无 USB 串口时）。排序元组扩为四元 `(接口分, 是否非by-id, 编号偏好, 序号)`，同分时稳定路径必定排在裸编号之前。

**前端**：串口下拉框按 `<optgroup>` 分组呈现「稳定路径（推荐，不受插口变化影响）」与「内核编号（可能随插口变化）」，AT 口条目附带提示；用户所选路径照常持久化到 UCI `serial_port`。

### 五、`sync_serial_by_id` 与同型号兜底

本机（ImmortalWrt SNAPSHOT, mediatek/filogic）**既无 udev 也无 mdev**，没有任何组件会创建 `/dev/serial/by-id`，故由 init.d 在服务启动时自行枚举并重建链接（位于 `bind_modem_serial` 之后、接口拉起之前，保证后端首次读配置时链接已就绪）。

**命名取组合键**：`usb-<idVendor>:<idProduct>-if<协议号>[-<iSerial 片段>][-n<N>]`

| 候选键 | 稳定性评估 | 是否采用 |
|:--|:--|:--:|
| `bInterfaceProtocol` | 设备内互不相同、跨主机不变、不随固件升级变 | **主键** |
| `iSerial` | **不保证唯一**（批次号+序号，同型号可能重复甚至为空） | 仅作可选片段 |
| `product` | 同型号必然相同、含空格、刷固件会变 | 不采用 |
| `bInterfaceNumber` | 随组合配置变化 | 不采用 |

**同型号兜底设计**：

- `iSerial` 为空 → 自动降级为不带该片段，链接仍然可用；
- **同型号撞名 → 追加 `-n2`/`-n3` 去重后缀**，保证不互相覆盖；
- 整批清理 `usb-*` 后重建（增量维护无法判断拔出设备对应哪个旧链接）；
- `ln -sf` 后以 `readlink -f` + `[ -c ]` 校验，失败即删除，不留断链。

### 六、busybox 与 rc.common 踩坑备忘

- **`tr` 的 POSIX 字符类在 busybox 下有缺陷**：`tr -d '[:space:]'` 会把 `s`/`p`/`a`/`c`/`e` 当**字面字符**删除（实测 `1c`→`1`、`0e`→`0`）；`tr '[:upper:]' '[:lower:]'` **完全无效**。故改用 `sed` 清洗 + `tr 'A-F' 'a-f'` 显式区间写法。
- **`printf '%02x'` 会把十六进制字符串按十进制解释**（`"12"`→`0c`），不能用于协议号转换。
- **`EXTRA_COMMANDS` 中的命令名必须与同名函数完全一致** —— rc.common 末尾执行 `$action "$@"` 按名查找函数，名字对不上时抛 `xxx: not found` 而非「未知命令」，极易误导。
- **`sanitize_id_part` 需将「纯点号」结果作废**：`.` / `..` 在路径语义中危险且无辨识价值。
