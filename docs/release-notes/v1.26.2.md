# v1.26.2

**主题**：短信中心按 IM 形态重做，并补上「自己发出去的短信」这条一直缺失的记录链。前者是界面，后者是协议语义逼出来的架构改动 —— `SMS-SUBMIT` 提交成功后模组**不写槽位**，`AT+CMGL=4` 读回来永远只有收到的那一半，所以发出记录只能由本插件自己留档。

---

## 1. 两个问题撞在一起

改界面的时候暴露出一个更根本的问题：**界面上根本没有自己发出去的短信**。

一开始以为是渲染漏了，查下来不是。3GPP TS 23.040 的 `SMS-SUBMIT` 提交成功（`+CMGS: <mr>`）之后，模组只把 MR 回给终端，**不往 SM/ME 里写任何记录**。`AT+CMGL=4` 列出的是存储区里的短信，发件箱那半从来就不在里面 —— 除非运营商回执（`+CDSI` / `TP-SRR=1` 的 status report）落进 MT，那也只是「送到了」的凭据，不是正文。

后果在时间轴上很直观：一次来回被拆成两截 ——「对方说的两句」挤在一起，「自己那句」根本不在。v1.26.1 的 `conversationOrder()` 里那句「发出短信没有时刻就排到末尾」的兜底，就是这个缺口的临时补丁。

所以这一版做两件事：

1. **后端自己留档**：收发双向都写进路由本地，按会话独立文件、加密存储、有配额上限；
2. **界面重做**：按 IM 形态排布，归档与模组存储合并成单条时间轴。

## 2. 归档为什么必须落在 `/etc`，而不是 `/var`

| 位置 | 实际挂载 | 断电/重启后 | 结论 |
|:--|:--|:--|:--|
| `/var` | → `/tmp`（tmpfs） | **全丢** | 不可用 |
| `/tmp` | tmpfs | 全丢 | 不可用 |
| `/etc` | overlay（持久化） | 保留 | **选定** |

目录固定为 `/etc/at-webserver/SMS`，与插件其余配置同源。目录**按需惰性创建** —— 没发过短信的路由器上不会凭空多出一个空目录。

文件名取 `sha256(归一化号码)` 的前 40 位十六进制，加 `.sms` 后缀。这样做的两个理由：

- **号码不出现在文件名里**：`ls` 一下看不见联系人是谁，与「加密防随手查看」是同一个威胁模型下的一致处理；
- **顺带规避路径穿越**：`/`、`..`、空格、`*` 这些在号码输入里可能出现的字符，都不可能进到文件名里。

### 容器格式

```
明文 JSON
  → ChaCha20 流加密（key = SHA-256(app_key ‖ salt)，salt 每文件随机）
  → 容器：魔数 "AWSS" | 版本 | salt | nonce | 明文长度 | 写入时刻   （共 48 字节头）
  → 整帧位置相关异或混淆
  → 尾部随机 padding（≤32 字节）
```

加异或混淆这一层不是为了更安全（密钥都在二进制里），而是为了让 `binwalk`、`xxd` 这类工具的「看着像结构化数据」的特征消失 —— 从外面看就是一团噪声。

尾部随机 padding 解决的是**长度旁路**：不补的话，文件大小 ≈ 明文长度，看一眼字节数就能猜出「这条短信大概几个字」。补 0～32 字节的随机量之后，至少要多看几次才能做统计。

### 配额与淘汰

| 层级 | 上限 | 超限处理 |
|:--|:--|:--|
| 单会话条数 | 500 条 | 丢最早 |
| 单会话文件 | 512 KB | 丢最早 |
| 目录总大小 | **2 MiB** | 淘汰水位 4/5（到 1.6 MiB 就开始清最早的会话/记录） |

2 MiB 的依据：一条 70 字中文短信的归档记录约 200 字节，2 MiB 足够存一万条左右，对路由器 overlay 是安全量级；而 `/etc` 写满的后果是**配置全丢**，这个上限必须保守。

### 威胁模型（如实说明）

- **防的是**：随手 `cat` / `xxd` / 把 overlay 拷出来直接搜关键字。
- **不防**：能执行本插件二进制的人（密钥是编译进去的常量）、能拿到设备完整 root 的人、能从内存 dump 里翻 key 的人。
- 如果需求是「连 root 都读不出来」，那得走 TPM / 安全启动那条线，不是这个量级的项目该做的事。

## 3. 三个真 bug，都不是「界面样式」层面的

### 3.1 `conversationOrder()` 拿对象当字典的键

```js
// 错：所有对象都会转成 "[object Object]"，每一条共用同一个键
var keyOf = {};
keyOf[msg] = { ms: ..., };

// 对：与数组同下标的平行数组
var keys = [];
keys[i] = { ms: ..., };
```

JS 的对象键会被强制转成字符串，`{}[obj]` 与 `{}[{a:1}]` 是同一个键。于是比较器拿到的 `kx` 与 `ky` 永远是同一个对象，`kx.ms - ky.ms === 0`，排序退化成最后那句 `sortIndex(x) - sortIndex(y)` —— **实际只按模组槽位号排**。归档消息没有槽位号（`null`），全被甩到会话最前面。

修完之后的实测顺序（真机 10000 那条会话）：

```
收 01:15:32 → 收 02:18:54 → 发 02:28:14 → 收 02:28:16 → 发 02:29:33 → 收 02:29:35
```

一次来回不再被打散。发出气泡里照旧标「时间未知」—— 借位置排序，不伪造时刻。

### 3.2 批量删除按钮创建了但没挂进 DOM

```js
var confirmBtn = Mt5700.dangerButton('删除所选', ...);
actions.appendChild(Mt5700.ghostButton('取消', close));
// 这里漏了 actions.appendChild(confirmBtn);
```

弹窗里只剩「取消」，**整个批量删除不可用**。这类漏写不报错、不告警，只在 UI 上静默消失一个按钮 —— 写完弹窗必须回头确认每个 `var xxx = ...Button(...)` 都真的 append 了。

### 3.3 状态报告占着真实槽位却禁止勾选

勾选框原来按 `m.error` 禁用：解析失败的 PDU 不许勾。问题是**解析失败 ≠ 不存在** —— 状态报告这类 PDU 确实占着 SM/ME 的一个格子，用户只能看着它吃存储额度、删不掉。

改成只看有没有真实槽位号；本地归档条目（模组里本来就没槽位）按 `m.archived` 单独放行。实测删除后存储 `used 15 → 14`。

> 顺带一个同源的根因（v1.26.1 留下、这一版才真正定位）：`mt5700.uc` 里 `sms.args` 的 `indices: ''`、`enable: ''` 这些**字面量默认值就是 rpcd 的类型声明**，不是注释。声明成字符串，前端传数组/布尔就被判 `UBUS_STATUS_INVALID_ARGUMENT`，JSON-RPC 上表现为 `{"result":[2]}`，**插件函数根本不执行**。这才是「能发送但读不到状态和记录」「提示模组拒绝但有时候能发出」两条现象的公共根因。ucode 也不是完整 JS，**不支持 `typeof`** —— `getBool()` 改用 `lc(trim('' + v))` 比对 `'1'/'true'/'yes'/'on'`。

## 4. 布局：会话内容多了不能把整页顶长

纯 CSS 算不出会话区的可用高度 —— 上方是 LuCI 导航栏、页签、hero（高度随主题、语言、屏宽变），下面是主题/页脚留下的空白，全是量不准的。所以：

1. `fitHeight()` 量 `layout` 的**文档坐标**，`innerHeight - top - 16` 定高；
2. 再量「整页实际溢出多少」，**从会话区里扣掉**，最多迭代 3 次直到整页不再滚动；
3. `render()` 返回时节点还没进文档，`rect.top` 是 0 —— 定高必须延后两帧，并在 400 ms / 1500 ms 各重校一次（hero 里的字体和图片是这时候才把高度撑到位的）。

滚动链隔离：消息区与列表都加 `overscroll-behavior: contain` + `touch-action: pan-y` + `-webkit-overflow-scrolling: touch`，滚到尽头不把滚动甩给整页。

实测：

| 尺寸 | docH / vh | 整页可滚 | 消息区内部滚动 |
|:--|:--|:--|:--|
| 1440×900 | 900 / 900 | 否 | 是 |
| 390×844 | 844 / 844 | 否 | 是 |
| 360×740 | 740 / 740 | 否 | 是 |
| 1280×700 | 751 / 700 | 是（51 px） | 是 |

1280×700 那 51 px 是**故意的**：再扣会话区就压到 320 px 以下，与其把消息区挤成一条缝，不如让整页滚一点。

手机端还有三处挤压，一并处理：

- 标题被操作按钮挤成「10…」→ 收紧按钮尺寸与间距；
- 窄屏点进会话后切不回去 → 补 `is-mobile-chat` 状态类与返回按钮（`showChat()`）；
- 主题自带的固定 `#floating-toolbar`（约 40 px）压住输入区 → 给 `.mt5700-sms-shell` 留 `padding-right: 52px` 让位。

## 5. 缓存：为什么升级后要硬刷新一次

LuCI 的静态资源只带 `ETag` / `Last-Modified`，**没有 `Cache-Control`**，浏览器按启发式规则自己决定缓存多久 —— 结果是 `sms_center.js` 换掉了，浏览器还在用旧的，界面上一切照旧，看起来就像「功能没做」。

- **CSS**：靠 `mt5700.css?v=` 破缓存，版本号由 `mt5700.js` 里的 `MT5700_CSS_VERSION` 驱动，这一版 2.29.0 → **2.37.0**；
- **view 模块（`sms_center.js`）**：没有版本参数，**升级后按一次 Ctrl+F5**。

同理，设备上部署完要清缓存：`rm -f /tmp/luci-indexcache*; rm -rf /tmp/luci-modulecache/; /etc/init.d/rpcd reload`（注意 indexcache 的真实文件名带 hash，只删不带后缀的那个会静默漏掉）。

## 6. 测试

- **后端**：`cargo test --release` **267 项：265 passed / 0 failed / 2 ignored**。新增 `sms_store` 11 项 —— 容器往返、指纹去重（同一条记两次仍是 1 条）、单会话条数淘汰、跨会话隔离、总配额超限淘汰最早、padding 不泄露正文长度、ChaCha20 与 SHA-256 均对权威向量交叉验证（RFC 8439 的 ChaCha20 参考值由本机 `cryptography` 库生成核对，SHA-256 跨多块向量由 `hashlib` 核对 —— 一开始凭记忆写的 RFC 向量第三、四段字节是错的，测试反而「通过」，这类自证必须用独立实现交叉验证）。
- **编译**：`cargo build --release` 零告警；`aarch64-unknown-linux-musl` 交叉编译通过（`zig cc` 同时作 linker 与 CC，产物 ELF64 / AArch64 / 静态 / 2.60 MB / 无 `PT_INTERP`），归档目录路径与 `AWSS` 魔数、`expand 32-byte k` 常量均确认编进二进制。
- **前端**：3 个 JS 语法校验通过（LuCI view 模块带顶层 `return`，`node --check` 不适用，改用 `new Function(src)`）。
- **实机（192.168.88.1，Hiveton-H5000M + MT5700M-CN）**：发送 `102 → 10000` → 归档 1 个会话 / 623 字节；`strings` 里搜不到 `10000` 与正文关键词、文件名是 sha256 前缀；`store_read` 读回同一会话的 `sent`（`timeApprox=true`）与 `received`；勾「同时删除本地记录文件」删掉那条 sent → 623 B → 460 B，收到气泡不受影响；批量删除 → 存储 `used 15 → 14`。

**验证边界（别当成全验过了）**：实机验证是**单机单卡**跑通的，只有一次发出记录（`102 → 10000`）。「多条会话并发归档」「2 MiB 配额真的触发淘汰」「手机端长会话滚动手感」这三条只在小规模/模拟条件下看过，没有跑到边界。加密强度按第 2 节的威胁模型理解，不要当成抗攻击存储。

## 7. 已知项

1. **`sms_store` 的读写竞态**：归档用「临时文件 + rename」替换，理论上写入与读取并发时读到的是旧文件而非空 —— 但实测里出现过一次 `store_read` 返回空，最终定位在 ucode 熔断（后端忙于处理到达短信），不是归档本身。为了稳，读取路径加了重试，长期仍建议改成读写锁。
2. **发出记录的时刻是近似的**：SUBMIT 里没有发送时刻（只有 TP-VP 有效期），归档用的是本机时钟且标 `time_approx=true`。设备时钟没同步时，这条时间会偏。
3. **多段长短信的归档粒度**：收到的长短信在拼装完成后按**合并后正文**记一条（槽位 `None`）；模组里那几段仍各自占槽位、各自可删。删除时两条线索（指纹 / 槽位）分别覆盖，但**删了模组槽位不等于删了归档**，需要勾「同时删除本地记录文件」。
4. **LuCI 内核的 `%s/%s.js%s.format` 偶发 pageerror**：来自 `luci.js:161` 的模块加载路径（`String.prototype.format` 竞态），与本次改造无关，不影响页面功能。

## 8. 升级方式

从 [Releases](https://github.com/LianXia233/luci-app-mt5700/releases) 下载对应架构软件包覆盖安装，配置向后兼容、无需迁移；归档目录会在第一次收发短信时自动创建。

装上后按这个顺序自测：

1. **硬刷新一次**（Ctrl+F5），确认会话列表与气泡左侧出现头像（对方粉色、本机薰衣草）、配色是蓝紫色系；
2. 发一条短信（本项目一贯用 `102 → 10000` 作测试口径），确认右侧立刻出现发出气泡并带头像；随后收起输入框、只滚消息区，页面本身不该跟着滚；
3. 手机会话页：能进能退（左上返回），输入框完整可见、不被浮动工具栏压住；
4. 单条删除与批量删除都弹「同时删除本地记录文件」勾选；勾上后到 `/etc/at-webserver/SMS` 看目录占用是否下降（`store_stats` 也能看）；
5. `cat` 一下 `SMS/` 下的文件，应该是一团噪声（不要用 `strings` 期待能读出正文）。
