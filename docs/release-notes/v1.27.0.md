# v1.27.0

**主题**：全局视觉收口（英雄区看板娘防遮挡 + 弹窗重做）、运行日志按类别细分、短信发出时刻改取插件 NTP 模块时间。要求很明确 —— **短信中心保持当前不变**，其余页面的样式与弹窗统一收拾一遍。

---

## 1. 看板娘为什么会被切、被盖

不是某条规则写错了，是 `mt5700.css` 长到 7200 行、里面叠了四套设计体系，同一个元素被不同世代的 `!important` 反复改写：

- `.mt5700-hero-card` 同时存在 `overflow: hidden` 与 `overflow: visible` 两条 `!important`，谁在后面谁赢 —— 而构建期会把同宽度的 `@media (max-width: 768px)` 块合并重排，胜负**随构建产物变化**；
- `.mt5700-hero-art` 在 960 / 768 / 640 三个断点被强拉成 `width: 100%`，头像那一栏于是把文字挤没，或者自己被卡片裁掉半边；
- 卡片里那团 `::before` 径向光斑（220px）和相邻卡片没有层级隔离，会盖到下一张卡上；
- 主题的 `#floating-toolbar` 是固定定位，窄屏时直接压在头像上。

结论：头像要**永远可见、永远完整**，靠「再补一条 !important」是补不动的。

## 2. 怎么修：顺序无关的权重 + 层级隔离

沿用项目里已经验证过的写法 —— 双类名 `.x.x` 叠权重、`:not()` 链做排除，这样无论构建器把哪个 `@media` 块排在后面，胜出的一定是这一批：

```css
.mt5700-hero-card.mt5700-hero-card:not(.mt5700-sms-hero-compact) {
  position: relative !important; z-index: auto !important;
  overflow: visible !important; isolation: isolate;
}
```

- `overflow: visible` 让头像不被卡片自己裁；
- `isolation: isolate` 让卡片自成层叠上下文：`::before` 光斑锁在 `z-index: 0` 且 `pointer-events: none`，既盖不住头像，也**不会溢到下一张卡片上**（这点比 `z-index: -1` 稳 —— 后者在祖先没成层叠上下文时会掉到页面背景后面）；
- `.mt5700-hero-art` 改 `width: auto` + `flex: 0 0 auto`，头像锁 76×76（`aspect-ratio: 1/1`，≤820px 收 64×64），层级 art:3 / avatar:4；
- 图片缺失时的兜底从原来那块 `#fbbf24` 黄色补丁换成紫粉渐变，不再出现「头像没了先变一块黄」；
- `prefers-reduced-motion: reduce` 下停掉 `mt-mascot-float`；
- 主题浮动工具条用 `@supports selector(body:has(*))` 包起来检测，命中时给卡片加 56px 右侧避让。原先这条避让只在 `max-width: 1199px` 生效，1280px 实测还差 6px 重叠 —— 视口越宽工具条未必越远，所以去掉宽度上限，只要工具条存在就让位。

## 3. 弹窗：从「定高 + hidden」改成三段 flex

老的两套世代各自为政（`z-index: 9999` 与 `z-index: 1000 !important`），且 `max-height: 85vh` 配 `overflow: hidden` —— 正文一长，footer 直接被切掉，按钮看不见、弹窗关不上。改法：

- 遮罩统一 `z-index: 9400`：**高于**主题 chrome（工具条/面包屑），**低于** toast 的 10000，通知不会被弹窗遮住；
- 本体 `display: flex; flex-direction: column; max-height: min(86dvh, 760px); overflow: hidden`，只让 `.mt5700-modal-body` 滚（`flex: 1 1 auto; min-height: 0; overflow-y: auto`）。`min-height: 0` 是关键 —— flex 子项默认 `min-height: auto`，不加就撑不破、滚不起来；
- footer `flex: 0 0 auto` 常驻可见，按钮 `min-height: 38px`、`flex-wrap: wrap`；
- ≤768px 转底部抽屉：遮罩 `align-items: flex-end`、贴底、顶部圆角 18px、进幕动画 `mt-modal-sheet-in`、`padding-bottom: env(safe-area-inset-bottom)`；
- 长串正文（PDU、日志行）靠 `overflow-wrap: anywhere` 收住，不再横向撑破。

顺带逮到一个不是本次引入的缺陷：`at.css` 从来没给 `.at-modal` 设过 `box-sizing`，`max-height` 因此落在 content box 上。768×900 实测盒体 846px > 视口可用 810px，内容一多就被顶出屏幕。补 `box-sizing: border-box`。

## 4. 怎么证明「短信中心一点没变」

口头保证没用，做了两层：

1. **结构层**：本次追加的 584 行 CSS 里，所有 SMS 相关选择器一律写作 `:not(.mt5700-sms-shell)` / `:not(.mt5700-sms-hero-compact)` / `:not(.mt5700-sms-modal)` / `:not(.mt5700-sms-modal-mask)` / `:not(.mt5700-sms-prompt)`。短信中心的四类弹窗（读详情 / 批量删除 / 删除确认 / 新短信输入）本来就各自带这些类，所以正向规则一条都命中不到它。唯一一处没被 `:not()` 包裹的是 `.mt5700-logcat-sms` —— 那是日志页的「短信」类别徽章，短信页面不用这个类名。
2. **实测层**：拿同一份短信中心 DOM（页面骨架 + 四类弹窗，54 个元素）分别在「本次追加之前」和「之后」两版 CSS 下加载，逐元素比较 49 项计算样式（display / position / z-index / overflow / flex / margin / padding / radius / 颜色 / 字号 / 行高 / white-space / box-sizing / transform / animation / isolation / backdrop-filter / pointer-events / 四边定位等），外加包围盒与文档横向溢出宽度。四档视口：

   | 视口 | 元素数 | 差异数 | scrollWidth（前 / 后） |
   |:--|:--|:--|:--|
   | 1280×900 | 54 | **0** | 1280 / 1280 |
   | 1280×700 | 54 | **0** | 1280 / 1280 |
   | 768×900 | 54 | **0** | 768 / 768 |
   | 390×844 | 54 | **0** | 390 / 390 |

   1280×700 与 390×844 是刻意挑的：这两档下短信 hero 本来就被 `display: none` 让位，正好验证「让位」规则没被全局规则推翻。

## 5. 运行日志：从一条时间轴到能筛

日志后端没动（还是 ringlog 的 `Entry { seq, ts, level, msg }`，`ts` 为毫秒，走 `mt5700.logs` RPC），改的是前端怎么读它：

- **类别**按消息内容归为 短信 / 拨号 / 网络 / AT / 系统 / 其他，规则表按优先级顺序匹配（短信在前，避免 AT 通道日志被抢走），每条挂一枚配色徽章，筛选做成带条数的胶囊按钮。复审时发现并修复了一处正则与意图不符：AT 通道层日志形如 `发送 → 模组: AT+CMGS=...`，原正则的 `SM` 子串匹配不到 `CMGS`（C-M-G-S），`CMGL`/`CMGR`/`CMGW`/`CMSS` 同样漏掉，这些短信收发痕迹会被归进「AT 通道」——现已在短信规则中列全 `CMGS|CMGL|CMGR|CMGW|CMSS|CMGD|CPMS`；
- **「仅错误+警告」**开关把 DBG/INF 收起来，排障时先只看 WRN/ERR（勾上时级别下拉视觉上回到「全部级别」，由这个开关接管）；复审时补了一处状态同步：勾选后再从级别下拉选别的级别，列表跟随新级别的同时自动清除勾选，不再出现「UI 显示 errors-only 生效、实际已不生效」的错位；开关本身 `accent-color: #ef4444` 跟随红色；
- **来源**可选后端环形日志或系统 syslog —— syslog 只认 `at-webserver:` 前缀，并显式跳过 `at-webserver-rust`，避免同一件事出现两份；
- **上限** 200 / 400 / 800 / 全部，默认 400；
- 跨天插 **sticky 日期分隔条**（`backdrop-filter` 压住滚过去的正文），长正文默认折 3 行、**只有真被裁掉才出「展开」**；底部一行统计「共 N 条 · 错误 / 警告 / 信息 / 调试」，导出头部附类别与来源。

「只有真被裁掉才出展开」这条踩了个坑：首次 `render()` 返回时节点还没被 LuCI 插进 `#view`，脱离文档的元素高度全是 0，`scrollHeight <= clientHeight` 恒成立，会把每条都误判成「没溢出」。改成推迟一个宏任务再量（`setTimeout(relaxFalseClamps, 0)`）。此前用 `if (!listEl.offsetParent) return;` 兜，同样不可靠 —— `offsetParent` 在 `position: fixed` 祖先下也是 null。

## 6. 发出时刻归 NTP 模块

`SMS-SUBMIT` 里没有发送时刻字段（只有 TP-VP 有效期），模组存完再读回来也给不出，所以这个章只能由插件自己盖。v1.26.2 盖的是**本机时钟**且一律标 `time_approx=true`；这一版改盖 `crate::nettime::now()` —— 全仓库唯一墙上时间入口，**NTP 校时结果优先，取不到才回退设备时钟**：

```rust
time_approx: !crate::nettime::from_ntp(),
```

于是语义从「永远是近似」变成「如实反映这一次」：NTP 已同步 → `false`，界面按精确时刻显示；刚开机还没拨上号 / NTP 不可达 → 仍 `true`，界面上继续写「（近似）」—— 断电重启后设备钟可能停在 1970 或出厂时间，把没对过的钟当精确时刻会直接误导排障。时间格式 `%y/%m/%d,%H:%M:%S`，与前端 `archiveKey` 同格式，可直接对齐；前端 `sentTimeAnchor()` + `mergeArchived()` 优先采用归档时刻，模组回读那份只用来保留槽位 `index`（删除要靠它）。

## 8. 已知项

1. **`PKG_VERSION` 未 bump**：`Makefile` 仍是 1.26.2，发布打包前需同步改成 1.27.0，否则包版本与 CHANGELOG 对不上。
2. **看板娘防遮挡只保证「不被切不被盖」**，不改它的大小与位置设计；如果某个主题把 hero 卡片本身藏了，那是主题的行为，不在本次范围。
3. **`@supports selector(body:has(*))` 依赖较新内核**：不支持 `:has()` 的老 WebKit 上，工具条避让不生效 —— 卡片仍完整，只是极端窄屏下可能被工具条压一角。
4. **日志类别靠消息文本匹配**：新增日志行如果措辞落进规则表前面几条，会被归到别的类别；调类别规则请改 `CATEGORY_RULES` 的顺序而不是加特例。
5. **syslog 来源依赖 `at-webserver:` 前缀**：若 rsyslog/system-logd 改了格式，该来源会读不到条目（后端环形日志不受影响）。

## 9. 升级方式

从 [Releases](https://github.com/LianXia233/luci-app-mt5700/releases) 下载对应架构软件包覆盖安装，配置与归档目录无需迁移。

装上后按这个顺序自测：

1. **硬刷新一次**（Ctrl+F5）—— view 模块不带版本参数，不硬刷新可能还是旧 JS；
2. 随便进一个非短信页面（网络状态 / 模组设置），确认看板娘完整、没被卡片切掉、也没压住下一张卡片；手机上再确认没被「保存 & 应用」那排按钮盖住；
3. 打开一个内容很长的弹窗（比如升级确认、协议列表），确认正文能滚、底部按钮一直在；手机上弹窗应从底部升起且贴着屏底；
4. 日志页：点类别胶囊筛选、勾「仅错误+警告」、切 syslog 来源、看底部统计与日期分隔条；手机上滚一条长正文，确认只有真被截断的那条才有「展开」；
5. 短信中心：确认与升级前一模一样；发一条短信（一贯口径 `102 → 10000`），NTP 已同步时发出气泡应带精确时刻、不再挂「（近似）」；批量删除里试一次「全选」。
