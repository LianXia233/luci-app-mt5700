## 1. 信号强度：从「色阶图例」换成「实测波束矩阵」

### 1.1 为什么要换

原「信号强度参考」是一张静态色阶图例：几条不同颜色的条带，配 -80/-90/-100/-110 四档文字。它的问题是**只说明「哪个值算什么水平」，不说明「现在实际是什么情况」** —— 用户看到图例里的「强」条带，再看右边的 RSRP 数字，还得自己在脑子里做一次对照。

5G NR 的波束赋形决定了一个服务小区会有多个 SSB 波束，各自信噪条件不同。这些数据模组本来就上报了，只是之前没人读。

### 1.2 数据来源

`AT^NRSSBID?` —— MT5700M-CN 5G 系列 AT 命令手册 **§13.28「NR SSB 测量结果上报」**（PDF pp. 378–381）。回包结构大致是：

```
^NRSSBID: <ARFCN>,<CID>,<PCI>,<RSRP>,<SINR>,<TA>,
          <SSB ID>,<RSRP>,<SSB ID>,<RSRP>, ...   ← 服务小区 8 组
          <邻区数>,<邻区 1 的 11 个字段>, ...
```

两个必须按手册处理的无效值：

| 字段 | 无效值 | 处理 |
| --- | --- | --- |
| SSB ID | `0xFF` | 置 `null`，该波束按「未上报」渲染 |
| RSRP / SINR | `0x7FFF` | 置 `null`，不当作数值参与分档 |

把它们当成数值用会得到 −127 dBm 之类的假读数和一堆误判为「差」的格子，所以解析阶段就切开，不在展示层补救。

### 1.3 展示

`rpc.js` 新增 `parseNRSSBID()`：按 SSB ID 归位（未出现的波束保留空位，不打乱顺序），邻区按上报数量逐个取，结构为空 / `ERROR` / 字段不足 / 入参不是字符串时一律返回 `null` 而不是抛错 —— 轮询里单次失败是常态，抛错会把整轮刷新打断。

矩阵为 4×2（桌面）/ 2×4（手机），每格显示 SSB ID、RSRP(dBm)、档位名。分档比原来细一档，并**把「无信号」单独作为一个状态**而不是塞进「差」：

| 档位 | RSRP 区间 | 色 |
| --- | --- | --- |
| 优 | ≥ −80 dBm | 绿 |
| 良 | −90 ~ −80 dBm | 青 |
| 中 | −100 ~ −90 dBm | 黄 |
| 弱 | −110 ~ −100 dBm | 橙 |
| 差 | −156 ~ −110 dBm | 红 |
| 无信号 | 未上报 | 灰 + 虚线边框 + 空心点 + 「—」 |

「弱」和「无信号」的区分做了三重冗余：边框从实线变虚线、圆点从实心变空心、数值从数字变「—」。只靠颜色区分对色觉障碍不可靠，靠数字区分又容易在暗色主题下被忽略。

实测最强的那个波束用同色细环标出，但**不写「主用波束」** —— 手册没定义「主用」，实测值最大的那个只是本次测量里最大的，编造一个语义会比不显示更糟。

轮询节流为每 3 轮（约 15 s）一次，失败保留上一次成功值。

### 1.4 链路拓扑

网络状态卡片从「信号塔图形 + 四个信息格」改为链路拓扑：**SIM 卡 → 蜂窝基站 → 数据网络**，节点间虚线流动 + 两端圆点错相呼吸（`prefers-reduced-motion: reduce` 下静止不动）。

之所以要这条链路，是因为运营商/频段/CA/IP 这几个字段原本并列摆放，看不出它们分属链路的不同环节 —— 「频段」是基站侧的，「IP 地址」是网络侧的，中间隔着 PDP 激活。现在按环节归位，并补上 IPv6 地址一栏（`pdpStackText()` 从 `+CGDCONT` 的 PDP 类型推出 `IPv4 / IPv6 / IPv4v6`）。

所有数据都取自既有 state，没有新增接口、AT 命令或后端调用。

## 2. 拨号成功后下发默认 DNS

### 2.1 配置项

集中在 UCI `at-webserver.config`，改配置即可换地址，不必碰脚本：

| 键 | 默认值 | 说明 |
| --- | --- | --- |
| `dns_enable` | `1` | 总开关 |
| `dns_v4_1` | `119.29.29.29` | IPv4 首选 |
| `dns_v4_2` | `223.5.5.5` | IPv4 备用 |
| `dns_v6_1` | `2402:4e00::` | IPv6 首选 |
| `dns_v6_2` | `2400:3200::1` | IPv6 备用 |
| `dns_exclusive` | `1` | 独占，`peerdns=0`，只用自己的 DNS |

### 2.2 优先级：它不只是「兜底」

原需求是「作为兜底值」，但实测 netifd 把 UCI 手写的 `dns` 排在 DHCP/RA 下发的 DNS **之前**（`/tmp/resolv.conf.d/resolv.conf.auto` 里的顺序可直接验证）。也就是说它同时是**实际优先使用**的那一个。这一点必须写在界面上，否则用户会以为「运营商给了 DNS 就不用我配的这个」，然后发现改配置没反应。

要真正忽略运营商 DNS 的，打开「独占 DNS」（默认开启）—— 对应 `peerdns=0`。

### 2.3 IPv6 的硬条件

**只有本次拨号确实拿到 IPv6 才写 IPv6 DNS。** 判据两条同时成立：

1. `AT+CGPADDR` 里某个激活 CID 带 IPv6 地址 —— 注意模组对 IPv6 有**点分十进制**的表示法（如 `36.9.141.90.3.72.0.236.0.0.0.0.0.0.0.1`），按「末段是 16 个十进制数」识别，不能只认冒号形式；
2. `AT+CGDCONT?` 里该 CID 的 PDP 类型是 `IPV6` 或 `IPV4V6`。

没拿到就清掉上一次留下的 IPv6 DNS。否则网络类型从 `IPV4V6` 退回 IPv4-only 时，解析会先试一个永远不通的 IPv6 地址，表现为「上网随机卡几秒」。

### 2.4 三态判定：把「不知道」和「没有」分开

`dial_has_ipv6` 返回三种结果：`0` 确认有 / `1` 确认没有 / `2` **无法判定**。

`reload_service` 会在**后端刚重启完**时触发重算，那一刻 ubus 的 `mt5700` 对象可能还没注册，AT 查询必然失败。第一版把失败当成「没有 IPv6」，结果是「改个 IPv4 DNS，IPv6 解析跟着挂了」—— 已于实机复现。现在无法判定时既不写也不清，保持现状。

这里「保守」的方向和 IPv4 相反：乱清会让正在用的 IPv6 解析凭空失效，比暂时不更新更糟。

### 2.5 生效与清理的时机

- **生效**：仅 `uci commit` 不会更新 `resolv.conf`，必须重启接口（实测）。因此 `reload_service` 里在接口处于稳态时补一次 `apply_default_dns`，让界面上改完保存即时生效，不必等下一次拨号。
- **清理**：挂在两个**明确且不会自我触发**的时机上 —— 下次拨号按实际情况重判、以及 `stop_service`。

**没有挂 hotplug `ifdown`**，这是试过两版才放弃的：netifd 的 `ifup` 语义是 down→up，必然伴随一次 `ifdown` 事件；而 hotplug 由 procd **异步**派发，标记文件挡不住延迟到达的那一发。两版自动清理都实测误伤 —— 要么「刚写完立刻被自己清掉」，要么「异步重算覆盖掉显式判定」。所以这个能力只保留手动入口 `on_downlink` 供排查用。

### 2.6 权限边界

`manage_interface=0` 时一律不写 DNS —— 那种模式下接口属于用户，写进去只会覆盖他手工配的解析服务器。

### 2.7 接口

- `on_uplink` 新增可选参数 `1|0` 显式声明本次是否拿到 IPv6（不传则自行经 `ubus call mt5700 at` 查 AT 判定，复用后端通道，不抢串口）；
- 新增 `on_downlink` 动作（手动排查用）。

## 3. 服务配置页排版压缩

### 3.1 问题

这页是纯表单，四十多个字段一行一个，说明文字又长。桌面端整页 **5332 px**，右侧大片留白；手机端 **6490 px**。

### 3.2 做法

| 端 | 手段 | 结果 |
| --- | --- | --- |
| 桌面 | 两列表单网格（`.mt5700-form-grid`）：字段各占一格，提示块与按钮行自动整行 | 5332 → **3430 px**（−34%） |
| 手机 | 单列不变，改「标签在左、控件在右」，一个字段只占一行 | 6490 → **4655 px**（−29%） |
| 两端 | 掐掉 `page-body` 的 `gap` 与卡片 `margin-bottom` 叠加出的 28 px 双重空档；提示字号、输入框内边距各降一档 | — |

路径过长需要整行的字段（串口选择器）用 `.mt5700-span-2` 显式占满。

### 3.3 过程中踩到并修掉的三个坑

- **按需分组全冒出来**：移动端横排用了 `display: grid !important`，内联 `style.display = 'none'` 压不住它 —— 「自定义串口路径」「IPv4/IPv6 接口名」在手机上全部展开。改用 `hidden` 属性 + 专用规则。
- **下拉框顶破卡片**：网格项的 `min-width` 默认 `auto`，作为 grid/flex 项会被解析成「内容最小宽度」，对 `<select>` 就是最长选项不换行的宽度（实测固定 210 px）。列宽小于它时溢出，1024 px 溢 9 px，768 px 溢 30 px。给网格内 `input`/`select` 显式 `min-width: 0; max-width: 100%`。
- **下拉框箭头被压掉**：压缩内边距时用了 `padding` 简写，把 `.mt5700-select` 原本给背景 SVG 箭头让位的 `padding-right: 40px` 一并覆盖，长选项文字压到箭头上、看起来像没有箭头。补回右侧内边距并对齐箭头位置。

另有一处一致性修正：「推送文案」卡片的「批量汇总标题」原本是普通单行 `input`，等宽字体、高度、边框都与相邻五个模板框不同，在同一张卡里明显像另一个控件，已改为相同的两行模板框。

## 4. 验证

- **SSB 解析**：`node tests/mock-modem/nrssbid-test.js` → **24 / 24 通过**（含实机真实回包、手册 §13.28.5 样例，以及空回包 / `ERROR` / 字段不足 / `undefined` 入参四条失败路径）；
- **实机 SSB 渲染**（192.168.88.1，ImmortalWrt SNAPSHOT / aarch64_cortex-a53）：RSRP −64 dBm，SSB 0~6 为真实值（−63 / −62 / −80 / −82 / −79 / −79 / −81 dBm），SSB 7 显示「无信号」，汇总行为「实测 7/8 · 最强 SSB 1」；桌面 4×86 px、手机 2×162 px，无裁切、无横向溢出；
- **DNS 下发**（实机 busybox awk 用例 5/5：点分十进制 / 冒号 / 纯 IPv4 / 多行 CGDCONT 定位）：
  - `on_uplink` 下发后 `resolv.conf.auto` 只剩我们的四条，运营商 DNS 不再参与解析；
  - 静置 20 s 无抖动（resolv 未被自己清掉）；
  - `on_uplink 0`（模拟本次无 IPv6）→ 清 IPv6、留 IPv4；`on_uplink 1` → 恢复；关总开关 → 清空；`on_downlink` → 只清 IPv6；

- **排版压缩**：375 / 480 / 640 / 768 / 900 / 1024 / 1200 / 1400 八档宽度扫描，`overflow = 0` 且 `scrollWidth ≤ innerWidth`；
- **回归**：网络状态页正常渲染，其它页面样式未受影响（压缩作用域用 `:has(.mt5700-form-grid)` 锁在本页）。

## 5. 升级注意

- **默认 DNS 独占是开启的**（`dns_exclusive=1`，即 `peerdns=0`）。升级后运营商下发的 DNS **不再参与解析**，解析全部走配置里的四个地址。如果所在网络有内部 DNS 或被运营商劫持策略影响，把「独占 DNS」关掉即可恢复「自己的 DNS 排前面、运营商 DNS 作后备」。
- 升级后如页面样式未刷新，硬刷新一次（`MT5700_CSS_VERSION` 已从 2.25.0 提到 2.28.0，正常会自动刷新）。
- 装包后 `postinst` 会合并 `/etc/init.d` 的 `.apk-new` 并重启 rpcd；`/etc/config/at-webserver` 的用户配置不会被覆盖（新版默认值只在首次安装时写入）。
- IMEI 相关代码零改动。
