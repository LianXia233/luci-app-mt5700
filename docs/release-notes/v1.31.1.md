**载波解析修复版** —— 修复 HFREQINFO 同行多组 NR 载波只解析第一组导致 SA CA 场景误显示单载波的缺陷；辅载波信号缺失时区分未上报、查询失败和不适用，前端显示可解释原因。

### 主要改动

- **fix(parse) HFREQINFO 同行多组载波解析**：`parseHFREQINFO()` 此前每行只解析 `p[2..8]` 作为第一组七字段载波，同一行后续 `p[9..15]` 被丢弃。SA n78+n78 场景中模组在同一条 `^HFREQINFO` 响应中上报两组 NR 载波，第二组因此丢失，页面误显示"单载波 (PCC)"。改为共享头 2 字段后每 7 字段一组循环处理所有完整七字段组，保留原有输出字段契约，单组/多行/多组均兼容；不完整行跳过，避免 `parseInt` 截断非法字段。
- **feat(parse) atStatusFromText**：新增 AT 终止状态检测函数，区分 OK / ERROR / NONE / empty / other。传输层成功（`sendCommand.success === true`）不等于 AT 命令成功——模组可能在传输正常时返回 ERROR 文本，此前无法区分。
- **feat(ui) SCC 信号缺失原因**：`syncCarriers` 为每个信号为空的 SCC 添加 `signalReason` 字段（`at-error` / `no-measurement` / `timeout`）；`renderCarriersAdv` 在 SCC 信号全部为空时显示可解释说明，如"已取得载波频点/带宽，未取得独立信号测量"或"辅站查询返回 ERROR"。绝不复制 PCC 读数或填 0。
