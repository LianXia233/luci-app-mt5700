# v1.24.2

**主题**：NTP **取到一次就本地计时**，20 分钟后再同步；失败按 `3 秒 ×10 → 1 分钟 ×10 → 20 分钟` 逐级退避。

---

## 1. 取到后本地计时，不再每次同步

同步只发生在后台任务里；`now()` / `now_ts()` / `now_ms()` 一律是
「**设备时钟 + 已记录的偏移**」的纯本地计算，**零网络开销**。

```rust
pub fn now_ts() -> i64 {
    crate::localtime::now().timestamp() + OFFSET_SECS.load(Ordering::Relaxed)
}
```

偏移在每次成功同步时更新（按「请求前 / 应答后」两个设备时刻的中点算，抵消一半往返延迟）。
两次同步之间时间靠设备时钟正常推进，不会因为没再同步就把时间冻住。

## 2. 同步节奏

```text
启动 ──► 同步一次 ─成功─► 记下偏移 ──► 本地计时 20 分钟 ──► 再同步 …
               │                                            ▲
               └─失败─► 3 秒 ×10 ─► 1 分钟 ×10 ─► 20 分钟 ───┘
                        （仍失败）      （仍失败）   （长期兜底，直到成功）
```

| 阶段 | 间隔 | 次数 | 覆盖窗口 | 目的 |
|:--|:--|:--|:--|:--|
| 第一级 | **3 秒** | 10 | ~30 秒 | 开机拨号 / 基站注册往往要十几秒才通，几秒后就好了 |
| 第二级 | **1 分钟** | 10 | ~10 分钟 | 拨号慢、短暂断网这类分钟级恢复 |
| 第三级 | **20 分钟** | 长期 | — | 确认网络长期不可达后的兜底节奏，避免每 3 秒空转 |

- **任何一次成功都会把连续失败计数清零**，回到 20 分钟节奏 —— 不会「曾经失败过就一直快重试」；
- 为什么每级给 10 次而不是 3 次：3 次（9 秒）太早放弃，会白白掉到分钟级，
  把「刚开机那半分钟」浪费掉；10 次能完整覆盖拨号与注册过程。

## 3. 实现

退避档位抽成**纯函数**（不碰全局状态，便于单测逐级钉住）：

```rust
pub fn backoff_for(consecutive_fails: u32) -> Duration {
    if consecutive_fails <= RETRY_FAST_TIMES {                          // ≤10 → 3 秒
        RETRY_FAST
    } else if consecutive_fails <= RETRY_FAST_TIMES + RETRY_SLOW_TIMES { // ≤20 → 1 分钟
        RETRY_MID
    } else {
        SYNC_INTERVAL                                                    // 之后 → 20 分钟
    }
}
```

`run()` 只维护一个 `CONSECUTIVE_FAILS` 计数器：成功清零，失败自增后交给 `backoff_for` 选档。

## 4. 验证

- `cargo test`：**197 passed / 0 failed，零警告**
- 新增 3 条用例：
  - `steady_state_resync_is_twenty_minutes` — 稳态间隔必须是 20 分钟，不能退化成「每次取时间都同步」；
  - `backoff_is_fast_then_slow_then_steady` — 逐级断言 1~10 次 = 3 秒、11~20 次 = 1 分钟、21+ = 20 分钟，并校验「越失败越慢」；
  - `backoff_zero_is_the_fast_lane` — 0 次失败的兜底档。
- 同时删掉了一条会与全局 `OFFSET_SECS` 抢状态的用例（测试并行跑时会互相干扰）。

## 5. 升级注意

- 纯后端行为调整，无配置项变更，可原地覆盖升级；
- 网络长期不可达时的最终节奏是 20 分钟一次（此前是 5 分钟），对 NTP 服务器更友好；
  设备时钟不准期间，流量卡仍会显示「时间源: 设备时钟」提示。
