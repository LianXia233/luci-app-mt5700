# v2.2.0 — WebUI 整包同步 main v1.24.3 + 流量使用量统计

**v2.2.0 把 `main` 分支 v1.24.3 的 WebUI 整包同步到本分支**，并把 main 同款的
「流量使用量统计」后端能力一并移植。自分叉基点 `eba64994` 以来，main 的 WebUI
已漂移约 1.4 万行（v1.15 Soft Anime 重构 + v1.16~v1.24 全量特性），本分支停留在
分叉时的旧版界面；本次以**逐文件决策矩阵**完成同步，仅保留两处本分支独立实现
（`service.js` 与 `rpc.js` 的 `loadConfig`），并在同步中修复三处真实不兼容。

### 背景

- **界面陈旧**：本分支 WebUI 停留在分叉时版本，缺失 v1.15 以来的 Soft Anime
  设计体系、mascot 形象、新版网络状态页等全部前端演进。
- **无使用量统计**：main 已具备「本月已用流量 / 峰值速率 / 自动清零」能力，
  本分支缺失；且实现上必须**不占用 AT 通道**（采样走 sysfs，不下发任何命令）。
- **同步即适配**：主线文件不能盲目覆盖 —— `rpc.js` 的配置加载基于 UCI，
  `service.js` 的服务管理基于 init.d，二者是本分支独立实现的根基。

### 同步决策矩阵（20 个文件）

| 类别 | 文件 | 处理方式 |

### 新增：流量使用量统计（从 main 同步）

- **feat(usage)** `src/rust/src/usage.rs`（~660 行）：
  - 常驻 **1 秒**采样 sysfs `/sys/class/net/<dev>/statistics/{rx,tx}_bytes`，
    **全程不下发 AT 命令，不占 AT 通道、不干扰模组**；
  - **负增量只重置基线**（计数器归零）不计入流量，杜绝重启/换卡导致的天文数字；
  - 双文件落盘：`/tmp/mt5700-usage.json`（tmpfs，重启即失）+
    `/etc/at-webserver-usage.json`（overlay，跨重启保留），落盘节流 5 秒；
  - 峰值速率按 1 秒粒度（5 秒 bucket 会把一秒突发压成五分之一）；
  - 状态文件 4 KiB 上限，超限视为损坏从零开始，绝不写出异常大的文件。
- **feat(monthly)** `src/rust/src/monthly.rs`（235 行）：自动清零的日历语义 ——
  目标日 00:00（本地时区）触发，大小月/闰年夹取到月末（31 号这类小月没有的
  日子按当月月末触发），跨年正确处理。
- **feat(httpserver)** 三个新路由：
  - `POST /api/rpc/mt5700/usage` —— 快照序列化；
  - `POST /api/rpc/mt5700/usage_ctl` —— `reset` / `persist_on` / `persist_off` /
    `set_reset_day`，未知动作 400；
  - `POST /api/rpc/mt5700/notify_test` —— 固定文案直发企业微信 WebHook，
    WebHook 为空显式报错。
- **feat(config)**：`Config` 新增 `usage_reset_day`（默认 1，合法区间 1~31，
  非法回落默认）；`debian/config.json` 同步新增 `"usage_reset_day": "1"`；
  网卡探测顺序为环境变量 `AT_WEBSERVER_NETDEV` → USB 网卡 → `eth2` 兜底
  （Debian 无 uci，去掉主线版对 uci 的依赖）。
- **feat(main)**：`UsageTracker::new(cfg.usage_reset_day)` + 启动时从配置注入
  netdev（`set_device`），spawn 常驻采样任务并加入优雅收尾 await。

### 同步中发现并修复的三处不兼容

1. **fix(webui) `Mt5700.formatDuration` 已不存在** —— 主线把 `formatDuration`
   从 `mt5700.js` 移到了 `rpc.js` 的 `AtWs` 门面；Debian 版 `service.js` 仍调
   `Mt5700.formatDuration`，不改将抛 TypeError 导致服务配置页**整页渲染失败**。
   已改为 `AtWs.formatDuration`（冒烟测试实测复现并确认修复）。
2. **fix(httpserver) `usage_ctl` 参数双键兼容** —— 前端 `rpcUsageCtl` 声明
   `params: ['action', 'days']` 且按位置传参，垫片序列化为 `{"action","days"}`；
   后端原只读 `day` 键，`set_reset_day` 恒收到 0 而保存失败。改为 `day` 优先、
   `days` 回落。端到端验证：`AtWs.usageCtl('set_reset_day', 15)` →
   垫片序列化 `days=15` → 后端双键读取 → `reset_day=15` 闭环。
   （注：主线后端同样只读 `day`，存在同款潜在缺陷；本分支不受影响。）
3. **fix(css) 补回主线丢失的移动端 Hero 规则** —— 主线 `mt5700.css` 的 768px
   媒体查询里 `.mt5700-hero-card`（`flex-direction: column-reverse` 等 4 条声明）
   与 `.mt5700-hero-title { font-size: 20px }` 两条规则被删只剩空白行。按本分支
   既有适配补回。桌面侧英雄卡尺寸（padding 18px 24px、gap 20px、220px、
   flex 1 1 420px、标题 21px 等）主线已全部覆盖，`hero-art` 主线演进为
   auto + `!important`（mascot 适配）更新，保留主线版。

### 新增：service.js 推送测试按钮

通知卡新增「推送测试」按钮：调 `/api/rpc/mt5700/notify_test` 用**已保存**的
WebHook 配置发一条固定文案；地址为空时前端先行提示，不必等后端报错。

### 升级说明

- 配置键 `usage_reset_day` 新增，默认 1（每月 1 号清零），不改变现有行为；
  网卡默认探测顺序不变（Debian 上通常即 `eth2`）。
- WebUI 整包替换，浏览器强制刷新（Ctrl+F5）即可，无需清理缓存之外的步骤。
- 持久化使用量文件落在 `/etc/at-webserver-usage.json`，卸载时如不需要可一并
  删除（`install.sh` 头部注释已列明卸载路径）。
