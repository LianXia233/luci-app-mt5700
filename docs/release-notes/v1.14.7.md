**Debian 分支 v1.14.7 为构建流程细分化与「前端产物保持未压缩」版**：将 `main` 分支 v1.14.7 的构建侧改动**按 Debian 环境等价移植**。

### main 侧原改动内容（供参考）

- `.github/workflows/build-openwrt.yml`：编译 job 细分为 8 个汉化步骤（检出代码 / 环境准备 / 依赖安装 / 构建执行 / 产物校验 / 日志归档 / 单包完整性校验 / 产物归档），发布 job 细分为 9 个汉化步骤。
- `scripts/sdk-build.sh`：引入 `SDK_BUILD_PHASE=deps|build` 两阶段拆分、中文阶段横幅、工具链卷复用。
- `Makefile`：新增 `LUCI_MINIFY_JS:=0`，并在 SDK `.config` 中写入 `# CONFIG_LUCI_JSMIN is not set`，**双重保险关闭前端 JS 压缩**，保证 `.js` 产物为未压缩源码。

### Debian 分支适配结论

| main 侧文件 | 是否移植 | 适配依据 |
| --- | --- | --- |
| `.github/workflows/build-openwrt.yml` | **不移植** | 本分支已彻底移除 OpenWrt/LuCI 构建体系，不存在 SDK 容器、apk/ipk 双包格式与 3 架构矩阵。该工作流在 Debian 分支无任何可执行对象，强行移植只会引入失效配置。 |
| `scripts/sdk-build.sh` | **不移植** | 同上，`scripts/` 目录在本分支不存在；Rust 后端由 `cargo build --release` 直接构建（见 `debian/install.sh`），无 musl 交叉编译与 zig 链接器需求。 |
| `Makefile`（`LUCI_MINIFY_JS:=0`） | **天然已满足** | 该开关的作用是阻止 LuCI 打包期压缩前端 JS。Debian 分支**不存在任何构建期压缩/打包逻辑**（全仓库无 `minify` / `uglify` / `terser` / `JSMIN` 相关代码），WebUI 为手写源码经 `cp -r` 直出、由后端 `serve_static()` 原样返回，浏览器拿到的始终是未压缩源码。 |

**结论：Debian 分支天然满足「产物未压缩」这一诉求，无需任何额外配置。** 相对于 v1.14.6，用户可感知的行为完全一致（页面 JS 为可读源码），实现路径由「打包期开关」变为「无打包期」。
