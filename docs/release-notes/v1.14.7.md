**v1.14.7 为 CI 工作流细分化汉化 + 关闭 JS 压缩版**：在 v1.14.6 基础上，重构 Actions 编译流程并保持产物 JS 未压缩。

### CI 步骤细分（编译 job，8 步）

1. 检出仓库代码
2. 环境准备（输出目录与构建参数）
3. 依赖安装（Rust 工具链 + zig 交叉链接器，SDK 容器内）
4. 构建执行（OpenWrt SDK 编译 LuCI 前端 + Rust 后端）
5. 产物校验（架构一致性闸门）
6. 日志归档（推送构建日志到 ci-logs 分支）
7. 产物校验（单包完整性与后端二进制闸门）
8. 产物归档（上传 Actions 构件）

发布 job 的 9 个步骤同步汉化；workflow 与两个 job 均显示中文名称。

### 阶段化构建脚本

- `scripts/sdk-build.sh` 新增 `SDK_BUILD_PHASE=deps|build|all`：依赖安装与构建执行可分两个 SDK 容器运行，`/opt` 工具链经宿主卷（`.ci-toolchain`）跨步骤持久化；`all` 模式与原单次完整构建完全兼容。
- 各阶段输出中文横幅：【依赖安装 1/3】基础工具 →【2/3】Rust 工具链 →【3/3】zig；【构建执行 1/5】定位 SDK →【2/5】放入软件包 →【3/5】feeds →【4/5】配置编译 →【5/5】收集校验产物。

### 关闭前端 JS 压缩

- 包级 `Makefile`：`LUCI_MINIFY_JS:=0`（覆盖 luci.mk 默认的 `?=` 值，JsMin 变空操作宏）。
- `sdk-build.sh`：.config 显式写入 `# CONFIG_LUCI_JSMIN is not set`，defconfig 后校验并输出中文确认。
- 双保险下无论 SDK 配置如何，产物内 .js 均保持未压缩源码。
