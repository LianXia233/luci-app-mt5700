**权限门禁加固版** —— 修复 Shebang 校验放行 UTF-8 BOM 与前导空白的假阴性，把「执行入口目录内每个脚本都必须登记」变成反向断言，并让权限清单覆盖仓库真实可执行面。只改 CI 门禁、测试脚本与文档，运行时脚本与页面渲染不变。

### 为什么改

- #54 的人工审查确认门禁方向正确，但 `isValidShebang` 对首行做 `.trim()`，会把 UTF-8 BOM 和前导空格/Tab 一起吃掉。内核只认文件头两字节 `#!`，BOM+LF 不含 `\r\n`，原有 CRLF 断言与 `static-check` 第 3 项都拦不住；BOM 恰是 Windows 编辑器的典型产物，正落在门禁声称要防的威胁模型内。实测修复前 `script-mode-test` 与 `static-check` 双双放行，修复后均失败。
- 原 7 项白名单与仓库实际 11 个 100755 blob 不重合，清单外 4 个全在 `tests/mock-modem/`；本仓库执行位回退已多次发生，「新增时记得登记」的注释约束正是历史上失效的那一类，因此把登记完整性本身变成断言。

### 主要改动

- **test(ci)** `isValidShebang` 不再 trim 首行，显式拒绝 BOM 与前导空白，只去掉行尾 CR；`hasUtf8Bom` 抽成共用函数（字符串 / Buffer 均可）；`static-check` 第 3 项由「行尾 LF」强化为「LF 且无 UTF-8 BOM」，覆盖全部 353 个文本文件；失败诊断用 `JSON.stringify` 输出原始首行。
- **test(ci)** 清单补齐至 12 项（含 `run-sim.sh`）；新增 `EXEC_ONLY_DIRS` 反向断言并并入 `static-check` 第 5 项（含子目录递归，失败指名路径）；检查项仍为五项，只增强不新增。
- **test(ci)** `NON_SHELL_EXECUTABLES` 标出两个 `#!/usr/bin/env node` 入口，`SHELL_SCRIPTS` 由主清单 filter 派生，权限与 Shebang 职责解耦，漏登记例外会 fail loud。
- **fix(test)** `git ls-files -z --` 避免 `core.quotePath` octal 转义误判中文路径、只认 stage 0、保留 stderr 与 `spawnSync` error；无 git 降级改为 `console.warn` 出声，不再静默 PASS。
- **docs(ci)** `checks.yml` 明确权限位 / 登记完整性归 `static-check`、Shebang / LF / BOM 归 `tests/script-mode-test.js`，同步 BOM 口径与符号链接说明；仅改注释与 step 名。
- **chore(release)** 版本号 1.32.9 → 1.32.10，按 AGENTS.md 清单同步全部版本引用与文档下载入口。
