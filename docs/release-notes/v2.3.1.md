# v2.3.1 — 批次三：推送与短信入口补齐、debian 收尾

**v2.3.1 把 v2.3.0 遗留的「功能在、入口无」空档补齐**：推送通道此前只能改配置文件，
短信中心与存储区因为缺 HTTP 路由而完全不可用。本版不引入任何新业务逻辑，
只把后端已有的能力接进独立 WebUI，并同步 `debian/` 的旧文案与新键样例。

> 版本口径：`src/rust/Cargo.toml` → `2.3.1`，`debian/build-deb.sh` 单点读取；
> CI 依版本号自动生成 `debian-v2.3.1`。`debian-v2.3.0` 是批次二中间状态被 CI 建出的 tag，
> **保持不动**（内容定稿由 2.3.1 承接）。

## 一、服务页新增的推送入口

全部走本分支既有的 `/api/config` 扁平键值，保存后由 `/api/config/apply` 判定是否重启
（这些通道都在后端启动时构造，故命中 `RESTART_KEYS` 会提示重启）。不依赖 ubus / UCI 包。

| 卡片 | 键 | 说明 |
| --- | --- | --- |
| 通知（扩展） | `notify_enabled` | 自动推送总开关；关闭后仅保留本地通知日志，信号巡检一并停止 |
| 通知（扩展） | `wechat_enabled` | 企业微信通道独立开关（此前只能改配置） |
| 定时推送 | `notify_timer_interval` | 1~1440 分钟，默认 10；另配 8 个常用间隔快捷项 |
| 信号定时巡检 | `notify_poll_enabled` / `notify_poll_start` / `notify_poll_end` / `notify_poll_interval` / `notify_poll_delta` / `notify_poll_all` | 采样间隔 30~3600 秒、阈值 1~30 dB；支持跨零点时段（22:00~06:00） |
| 信号定时巡检 | `notify_signal_min_interval` | 0~10080 分钟，0 不限频；只约束事件驱动的信号通知，短信与来电保持实时 |
| QQ 推送 | `qq_enabled` / `qq_app_id` / `qq_app_secret` / `qq_target_type` / `qq_target_id` / `qq_bind_qq` / `qq_msg_format` / `qq_max_per_minute` | 目标类型 group / c2c / channel / bind；AppSecret 可留空改用环境变量 `QQ_BOT_APP_SECRET` |

数值输入在前端统一夹到后端接受区间，避免手输越界后被后端静默回落。

## 二、两个「未新增卡片」的键，及取舍理由

- **`usage_source`（流量统计来源）**：状态页「统计来源」下拉已通过
  `/api/rpc/mt5700/usage_ctl` 的 `set_source` 即时换源，后端同时写回配置、**无需重启**。
  若在服务页再放一个配置项，会出现「两处都能改、其中一处要重启」的割裂，故不重复。
- **`sms_storage`（短信存储区）**：由短信设置页经 `mt5700.sms` 的存储区动作写回，
  后端同步 `config.json`。它本质是「模组侧动作 + 配置」，单独做一个输入框会与模组
  实际存储区不一致，因此靠 RPC 保持一致，而不新增配置输入框。

## 三、短信路由（本次最实质的修复）

`rpcserver.rs` 的 `handle_sms` 一直是私有 `async fn`，TCP RPC 通道能调、HTTP 层拿不到，
导致独立 WebUI 的短信中心、存储区、归档页全部报错。

- 新增 `RpcServer::sms_action(action, params)`：调用 `handle_sms` 并把 TCP 的
  `{id, result|error}` 信封拆平 —— 成功给 `result` 对象，失败给错误文案（保留 `sms_busy:` 前缀）。
- 新增 HTTP 路由 `POST /api/rpc/mt5700/sms`：请求体即参数字典（含 `action`），
  失败按前端 `rpc.js` 的约定平铺为 `{"success": false, "error": "..."}` 且**保持 200**。
  用 5xx 会让前端熔断器把「模组回 ERROR」误判成「后端不可用」，进而停发所有请求。

## 四、清理与收尾

- 删除 `webui/luci-static/resources/at-webserver/smsEncode.js`（`main` v1.25 起已删除，
  编码并入 `rpc.js`，本分支此前仍在预加载）；`app.js` 预加载顺序 10 项 → 9 项。
- `debian/install.sh` 卸载说明的旧路径 `/etc/at-webserver-usage.json`
  改为实际的 `/etc/mt5700/usage.json`。
- `debian/config.json` 补 20 个新键示例（推送、巡检、QQ、`usage_source`、`sms_storage`），
  QQ 凭据一律留空占位。
- 依赖声明复查：`Depends` 由 `build-deb.sh` 按二进制 `NEEDED` 自动推导；
  批次一新增的 `tokio-tungstenite` / `rustls` 为静态链接、`webpki-roots` 内置根证书，
  不产生新的运行时包依赖，无需手工追加。
- 补回 `.mt5700-author` 页脚（作者署名 + 主仓库链接）。仓库的「作者署名保护规则」
  要求该元素在 UI 重构/迁移中必须保留，本分支 Debian 化时曾丢失，本版按原样补回，
  并置于底部保存操作栏之后。
- 接入 `Ui.startup(page, null)` 统一启动入口（与其余 11 个视图一致，负责 `at.css`
  注入与全页一致的浮动提示条）。
