# v1.14.14 发布说明

**v1.14.14 为通知与状态显示版**：新增 QQ 机器人推送通道（含后端自动绑定与 LuCI 运维工具），修复网络状态页错选 IMS 信令承载导致 APN/QCI/AMBR 显示假数据的缺陷。**未触碰任何 IMEI 相关代码与数据流**。

## 一、QQ 机器人推送通道（官方 API v2，核心新增）

- 鉴权：`POST https://api.bot.qq.com/app/getAppAccessToken` 换取 `access_token`，服务内缓存并在过期前 120 秒锁内单飞刷新；**显式检查业务码**（错误 Secret 时 QQ 返回 HTTP 200 + `code=100016`，只看 HTTP 状态会误判成功）。
- 推送目标三选一：群 / 单聊（C2C）/ 频道；复用既有通知链路（四类事件、60 秒合并窗口、3 次重试退避）。
- 配置：UCI `qq_app_id` / `qq_app_secret` / `qq_target_type` / `qq_target_id`；密钥支持环境变量 `QQ_BOT_APP_ID` / `QQ_BOT_APP_SECRET` 优先注入，避免凭据落盘。

## 二、openid 自动绑定（bind 模式）

- 背景：QQ 开放平台不提供「QQ 号 → openid」转换接口，openid 只能从 WS 网关事件获得（QQ 号直接当 openid 发 C2C 实测 code 11255）。
- 流程：UCI `qq_target_type='bind'` → 服务启动连 WS 网关 → 用户给机器人发一条消息 → 提取 openid **写回 UCI 并热替换通道（无需重启）** → **立即回发一条绑定成功确认消息**。
- LuCI「绑定进度」区域每 2 秒轮询 `qq_bind_status`：等待中显示 **600 秒窗口倒计时**、成功显示目标、失败显示原因。

## 三、LuCI 运维体验

- 通知卡片新增「发送测试通知」按钮：按已配置通道（企业微信 / QQ）并行探测，逐通道汇报成功/失败原因，绕过合并窗口直发。
- QQ 表单：AppID / AppSecret（密码框）/ 目标类型（含 bind）/ 绑定 QQ 号（仅标签）/ 目标 ID。

## 四、网络状态页承载选择修复

- 原实现取**编号最小**激活 cid，IMS 信令承载（`ims`，QCI=5，30/30 Mbps）cid 最小时被误选，APN/QCI/AMBR 全显示假数据。
- 现改为遍历全部激活 cid 逐个查 `AT^DSAMBR`，**跳过 `ims`/`sos`/`emergency`** 锁定互联网承载，兜底取下行速率最大；QCI 按该承载 cid 定位 `AT+CGEQOSRDP` 行。实机验证：APN=`3gnet`、QCI=6、AMBR 3000/300 Mbps。

## 五、依赖与验证

- 依赖：Rust 新增 `tokio-tungstenite` 0.24（rustls webpki-roots，仅绑定模式短暂连网关）与 `futures-util`（sink）。
- 验证：`cargo test` 43 passed / 0 failed / 2 ignored（真实接口冒烟走环境变量，凭据零硬编码）；`node --check` 全部前端改动通过；实机部署全链路验证（QQ 推送送达、绑定确认消息、APN/QCI/AMBR 正确）。
- 已知限制：推送均为主动消息，受官方频控（群 30~60 条/分钟、单关系 20 条/分钟、1000 条/群/天）与用户端「允许主动发送」开关约束；频道推送要求机器人 WS 在线。
