# v1.21.1

**主题**：修正签约速率的查询上下文——只取数据上网那条，不取 IMS。

## 问题

v1.21.0 里 `AT+C5GQOSRDP=` 后面的 CID 是**写死的 1**。

本机实况（`AT+CGDCONT?` / `AT+CGACT?`）：

```
+CGDCONT: 1,"IPV4V6","",...      ← 数据上网承载，APN 为空（核心网分配）
+CGDCONT: 5,"IPV4V6","ims",...   ← IMS 专用承载
+CGACT: 1,1                      ← CID 1 已激活，CID 5 未激活
```

所以本机数值没错（CID 1 正是上网承载）。但**写死 CID 1 在别的拨号配置下就会查错上下文**——如果某张卡的数据上下文不是 1，或者 1 被用作 IMS，显示出来的就不是上网速率了。

## 修正

1. **改用数据通道 CID**：查询参数改为 `pickDataContext()` 选出的 `state.apnCid`。该函数会剔除 IMS / 紧急 / MMS / SUPL 等专用承载 APN，因此拿到的必然是数据上网上下文；只有解析不到时才退回 CID 1（默认数据上下文）。

2. **IMS 兜底防护**：若返回的 5QI 是 **1（VoLTE 语音）或 5（IMS 信令）**，即 IMS 承载的特征值，判定查到的不是上网速率，直接不显示。

3. **每次刷新都重置**：查询失败或拿到 IMS 承载时把 `state.subRate` 清空，避免切网 / 摘卡后残留上一次的数值。

## 实机验证

| 项目 | 结果 |
|:--|:--|
| 数据通道 (CID) | 数据上网承载的 CID（IMS 的 CID 已被剔除） |
| 签约速率 | 正常显示上下行数值 |
| 悬停说明 | 「数据上网上下文（CID N，已剔除 IMS 等专用承载）的 Session-AMBR …」 |
