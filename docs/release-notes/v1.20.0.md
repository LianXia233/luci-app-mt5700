# v1.20.0

**主题**：流量统计卡片新增「本次使用量」统计 —— 设备侧累计，刷新不失效、重启归零、可选持久化、支持清零。

## 需求

- 「在流量统计卡片里加入使用量统计，**数据存到内存**」；
- 「是刷新不失效，**直到重启后**」；
- 「用户可选持久化，加个小按钮，支持清零」；
- 「减少写入频率，防止消耗闪存寿命」。

## 为什么放在设备侧

浏览器内存里的累计值一刷新就归零，所以累计必须由**设备侧**持有。

设备侧的接口计数器 `rx_bytes` / `tx_bytes`（`/sys/class/net/<dev>/statistics/`）是**单调递增**的累计值，只要累加「相邻两次采样的增量」，即使中间浏览器关闭、页面刷新，下一次采样也会把这段时间的流量一并补上，不会漏计。

### 记录时机：是「前端打开才累加」，但效果等价于「后端一直记录」

累加代码在 rpcd 的 `netrateCall()` 里，由前端 `setInterval(sampleRate, 1000)` 每秒触发一次 —— **页面关闭期间确实不会逐秒累加**。

但因为底层计数器单调累计，重新打开页面时会把关闭期间的全部增量一次性补上。实机核对（页面完全关闭 30 秒、期间持续下载）：

| 测量点 | 相对累加器基线的内核增量 |
|:--|--:|
| 关页面 30s 后 | 94.44 MB |
| 重开页面后 | 102.38 MB |
| **页面显示值** | **101.28 MB** |

关闭期间那 94.44 MB 被完整补记，页面值与同期内核增量仅差 1.07%（残差为页面 1 秒采样粒度）。

**唯一例外**：关闭期间若承载网卡计数器归零（接口 flap / 重新拨号），该段增量无法补记，重新驻网后从新基线开始累计。

## 存储策略（兼顾「刷新不失效」与闪存寿命）

| 场景 | 落点 | 是否碰闪存 |
|:--|:--|:--|
| 默认（持久化关） | `/tmp/mt5700-usage.json`（tmpfs） | **否** |
| 开启「持久化」 | 额外写 `/etc/at-webserver-usage.json`，每 **10 分钟**最多一次 | 是（低频） |
| 重启后 | `/tmp` 被清空 → 自动读 `/etc` 里的持久化文件恢复 | 只读一次 |

要点：

- **稳态只读 tmpfs**：`loadUsage()` 优先读 `/tmp`，只有它不存在（重启后）才读 `/etc`，日常运行完全不触碰闪存。
- **落盘节流**：`USAGE_FLASH_INTERVAL = 600`（10 分钟），代价是重启后最多回退 10 分钟用量，对使用量统计完全可接受。
- **边界处理**：计数器归零（接口 flap）表现为负增量，此时**只重置基线、不累加**，避免把一次归零误记成一笔巨额流量；峰值只在正常采样节拍（1~5s）内计算，避免把「页面隔了很久再打开」的低均值当峰值。

## 新增 RPC

| 方法 | 参数 | 说明 |
|:--|:--|:--|
| `mt5700.netrate` | `device` | 既有方法，返回值**新增 `usage` 字段**（下行/上行累计、起止时间戳、峰值、持久化开关） |
| `mt5700.usage_ctl` | `action` | `reset`（清零）/ `persist_on` / `persist_off` / 其余为纯查询 |

两者均在 `root/usr/share/rpcd/acl.d/luci-app-mt5700.json` 的 read / write 白名单中放行。

## 界面

「流量统计」卡片底部新增 `本次使用量` 分区，含两个小按钮：

- **持久化**：开启后写入闪存、重启后保留（按钮高亮表示已开启）；
- **清零**：清零本次累计，持久化开关状态保留。

数据网格：下行 / 上行 / 合计 / 采样时长 / 峰值速率（窄屏自动折成两列 + 一行通栏）。

## 实机验证

后端（ubus）：

| 操作 | 结果 |
|:--|:--|
| `netrate` 连续调用 | `total_rx` / `total_tx` 正常增长，`peak_rx` / `peak_tx` 记录峰值 |
| `usage_ctl reset` | 累计与峰值归零 |
| `usage_ctl persist_on` | `persist:1`，`/etc/at-webserver-usage.json` 生成 |
| `usage_ctl persist_off` | `persist:0`，落盘文件删除 |
| 模拟重启（删 `/tmp` 状态文件）后再 `netrate` | 从闪存恢复 `persist:1` 并继续累计 |

前端（Chrome，桌面 1280px + 手机 360px）：

| 操作 | 结果 |
|:--|:--|
| 初始 | 下行 17.61 MB / 上行 2.57 MB / 合计 20.18 MB / 时长 00:00:41 |
| 等待 7s | 合计 22.46 MB，持续增长 |
| 点「清零」 | 归零后重新累计（1.07 MB） |
| 点「持久化」 | 按钮高亮，`persistOn: true` |
| **刷新页面** | 数值保留（合计 5.59 MB），持久化仍为开 |
| 360px | 两列布局、无横向溢出 |
