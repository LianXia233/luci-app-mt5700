# v1.24.1

**主题**：全局时间统一走 `nettime`（NTP 优先、设备时钟回退），**时区仍然读设备**；间隔测量改用单调时钟。

---

## 1. 为什么改

v1.24.0 引入了 NTP 时间源，但只有「使用量按月清零」和日志时间戳走它，其余模块仍在各自取
`localtime::now()` / `SystemTime::now()` —— 也就是**设备时钟**。后果是同一台机器上存在两条时间线：

| 场景 | v1.24.0 | 后果 |
|:--|:--|:--|
| 日志时间戳 | nettime（校正后） | — |
| 通知文案 `{time}` | 设备时钟 | 日志 03-01 00:00 清零，通知却写 02-28 23:52 |
| 短信 PDU 时间兜底 | 设备时钟 | 模组没给时间戳时，短信时间比日志早 |
| 巡检时段判定 | 设备时钟 | NTP 校正后「该推的时段」可能整段跳过 |
| 定时锁频 | 设备时钟 | 夜间/日间切换点对不上系统时间 |

设备刚上电还没拨号时 NTP 取不到，两条线可以差好几分钟甚至更久（无 RTC 时差几个月）。

## 2. 改成什么样

**绝对时刻（「现在几点」）→ `nettime`**

| 模块 | 改动 |
|:--|:--|
| `logger.rs` | 日志时间戳：`now_ms()` / `timestamp()` 走 `nettime` |
| `async_runtime.rs` | 任务创建时间走 `nettime::now_ms()` |
| `pdu.rs` | 短信 PDU 时间戳解析失败/越界的兜底 → `nettime::now()` |
| `notify.rs` / `urc.rs` | 通知与 URC 的 `{time}` → `nettime::now_string()` |
| `signalwatch.rs` | 巡检时段判定 `minute_of_day_now()` → 基于 `nettime::now()` |
| `schedule.rs` | 定时锁频的当前时刻与日志 → `nettime::now()` |

`nettime` 内部回退链：**NTP（三个服务器依次）→ 设备时钟**，失败只是一条 WARN，功能不受影响。

**时区仍然读设备**

`nettime` 只校正 **UTC 时刻**，时区一律沿用 OpenWrt 系统设置：

```text
时刻：NTP → 设备时钟（localtime::now 即设备时钟底座）
时区：/etc/TZ → uci system.@system[0].timezone → 北京时间 UTC+8
```

两者正交。`localtime` 由此收敛为**纯时区层**：删掉了已无人调用的
`now_string()` / `minute_of_day_now()`，只保留 `offset` / `from_unix` / `from_ymdhms` /
`describe` / `init`，以及作为回退底座的 `now()`（业务代码不要直接调它）。

**间隔测量 → 单调时钟（不碰墙上时间）**

`atclient` 里「长命令结束于何时」原本用 `SystemTime` 存墙上时间戳再算差值。NTP 校正会让这个
差值凭空跳变（甚至变负）。改为基于 `Instant` 的进程单调毫秒 `mono_ms()`：

```rust
fn mono_ms() -> u64 {
    static ORIGIN: std::sync::OnceLock<Instant> = std::sync::OnceLock::new();
    ORIGIN.get_or_init(Instant::now).elapsed().as_millis() as u64
}
```

原则：**AT 超时、节流、凭证有效期、任务耗时一律用 `Instant`；只有「展示给人看」和
「按日历判定」才用墙上时间。**

## 3. 约定由测试兜底

新增源码级回归用例 `nettime::tests::no_direct_wall_clock_outside_time_modules`：扫描 `src/`
下除 `localtime.rs` / `nettime.rs` 外的所有 `.rs`（**剥离注释后**匹配，所以「为什么不能用
`chrono::Local`」这类说明不会被误判），一旦出现 `chrono::Utc::now()` / `chrono::Local` /
`SystemTime::now()` 就测试失败。以后谁再手写墙上时钟，CI 直接拦下来。

## 4. 验证

- `cargo test`：**194 passed / 0 failed，编译与测试均零警告**
  （v1.24.0 为 195：删除 `localtime` 已废弃的 2 条用例，新增 1 条回归用例）
- 全局扫描确认：`src/` 中除 `localtime.rs` / `nettime.rs` 外已无任何墙上时钟调用点
- 前端与 ucode 未改动（本次纯后端时间源收敛）

## 5. 升级注意

- 纯后端改动，无配置项变更，可原地覆盖升级；
- 若设备长期 NTP 不可达，行为与升级前一致（全部走设备时钟），只是日志/通知/清零判定
  现在**共享同一个**设备时钟，不再各读各的。
