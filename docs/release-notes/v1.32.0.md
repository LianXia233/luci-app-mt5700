**流量统计口径修正版** —— 实时速率与「本次使用量」只统计 WAN 区域里模组创建的物理网口，彻底排除 `br-lan` 与 LAN 侧网卡；新增统计来源手动开关（物理网卡计数器 / 模组 `AT^DSFLOWQRY`）；DNS 下发目标改为按「USB 模组网口 + WAN 区域」自动反查，全程不绑定具体网卡名或接口名。

### 主要改动

- **fix(usage) WAN 区域自动识别**：旧实现的解析顺序是 `MT5700M → 绑定模组网口的接口 → LAN → br-lan`，模组接口未创建或绑定失效时会回落到 LAN 网桥；实机 LAN 网桥上行计数器超过 200 GB，绝大部分来自 Wi-Fi 与内网互传，计入后把蜂窝用量放大一到两个数量级。Rust `usage.rs` 与 rpcd ucode 现在各用一次 `uci show firewall` + 一次 `uci show network` 解析，递归展开 `@别名`，按 USB 总线判据定位模组网口，优先级为「WAN 区域 ∩ USB 模组网口 → WAN 区域其它物理网口 → 候选全无时非 LAN 归属的 USB 网卡」。显式排除 `br-lan` / `br-lan.*` / `lo` / LAN 区域网卡；全部失败时停止采样（累计值保留），绝不回退 LAN。
- **fix(netrate) 入参校验**：旧 `netrate` 允许显式传入任意 `device`，手工传 `br-lan` 可直接读到该计数器。现在显式入参必须与自动识别结果一致，LAN 侧入参一律忽略；识别不到 WAN 网卡时返回 `success:false`，不再伪装成 0 流量。
- **feat(usage) 统计来源开关**：新增 `at-webserver.config.usage_source`（`netdev` 默认 / `modem`），可在「网络状态 → 本次使用量 → 统计来源」里切换。`netdev` 直读 `/sys/class/net/<dev>/statistics/{rx,tx}_bytes`，1 秒采样、零 AT 负担；`modem` 读取已在状态缓存白名单里的 `AT^DSFLOWQRY`（AT 手册 16.12，DS 累计收发为 16 位十六进制字节数），采样间隔对齐 2 秒刷新。切换写 UCI 并热更新，`device` 标签变化触发重新基线、累计值保留，避免两套计数器差值被误记成巨额流量。清零只重置插件侧累计，不下发 `AT^DSFLOWCLR`，不触碰模组全局计数。
- **feat(usage) 速率同口径**：`modem` 来源下 `netrate` 由 ucode 转发到 Rust 后端新增的 `netrate` 方法，返回与使用量同一份 DS 累计值；`netdev` 仍由 ucode 直读 sysfs。
- **feat(dns) DNS 下发目标自动反查**：init.d 新增 `iface_in_wan_zone` / `dns_direct_ifaces` / `dns_alias_ifaces`，按「USB 模组网口 + WAN 区域」反查所有承载接口；IPv4 DNS 下发给直接绑定接口、IPv6 DNS 下发给 `@别名` 接口，清除时覆盖全部曾下发接口，避免残留。同时移除 USB 探测中对 `eth0|eth1` 的硬编码跳过，改由 USB 总线判据决定。
- **refactor 冗余清理**：删除两侧旧接口选择函数（`FALLBACK_NETDEV` / `select_netdev` / `detectModemDevice` 等）；init.d 的 DNS 反查复用既有 `modem_direct_ifaces()` / `alias_ifaces_of()`；`usage.rs` 的 `set_reset_day()` / `set_source()` 抽出公共 `uci_set_config()`。
