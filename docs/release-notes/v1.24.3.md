# v1.24.3

**主题**：修复 CI —— 中间态 commit 不再触发完整构建（陈旧提交自动跳过）。代码本身无缺陷。

---

## 1. 故障现象

v1.24.1 的批量改动推送后，CI 出现 6 个架构矩阵**全部红叉**，失败步骤统一是
「构建执行（OpenWrt SDK 编译 LuCI 前端 + Rust 后端）」：

```text
error[E0425]: cannot find function `minute_of_day_now` in module `crate::localtime`
   --> src/signalwatch.rs:410
error[E0425]: cannot find function `now_string` in module `crate::localtime`
   --> src/urc.rs:146 / src/urc.rs:162
```

## 2. 根因：逐文件推送产生了「改了一半」的中间态 commit

本次改动横跨 10 个源文件，而推送方式是 GitHub Contents API —— **一次只能写一个文件**，
于是每个文件都是一个独立 commit，`push` 事件**逐 commit 触发**一次 workflow：

| 顺序 | 落地的 commit | 该 commit 的状态 |
|:--|:--|:--|
| 第 1 个 | `localtime.rs` 删除 `now_string` / `minute_of_day_now` | **编译不过**（调用方还在用旧函数） |
| 第 2~N 个 | `signalwatch` / `urc` / `notify` 等改走 `nettime` | 逐步收敛 |
| 最后 1 个 | 全部改完 | 正常 |

中间那些 commit 天然编译不过。24 个 run（19 个文件 + 后续几次推送）排队，
每个都要跑 6 个架构的 SDK 编译，既浪费额度又留下一串红叉。

**验证代码本身没问题**：拉取 main 最新代码单独执行 `cargo build --release`
—— 通过、零警告；本地 `cargo test` 197 passed。所以这不是代码缺陷。

## 3. 修复

### 3.1 CI 侧：陈旧提交跳过（本次改动）

build job 新增一步「陈旧提交检查」，用 `git ls-remote` 比对分支 HEAD：

```yaml
- name: 陈旧提交检查（已被后续提交取代则跳过构建）
  id: stale
  run: |
    stale=false
    if [ "${{ github.event_name }}" = "push" ] && [ "${{ github.ref_type }}" = "branch" ]; then
      head=$(git ls-remote https://github.com/${{ github.repository }} "refs/heads/${{ github.ref_name }}" | cut -f1)
      if [ -n "$head" ] && [ "$head" != "${{ github.sha }}" ]; then
        stale=true
      fi
    fi
    echo "stale=$stale" >> "$GITHUB_OUTPUT"
```

后续「依赖安装 / 构建执行 / 产物校验 ×2 / 产物归档」五步统一加
`if: steps.stale.outputs.stale != 'true'`；release job 加
`if: needs.build.outputs.stale != 'true'`（构建被跳过时不能发布，否则缺产物必失败）。

tag 推送与手动 `workflow_dispatch` 不受影响 —— 它们本来就是终态。

### 3.2 并发策略**故意不改**

`concurrency` 仍然按 `github.sha` 分组、`cancel-in-progress: false`：

一次发布会同时产生 **main push + tag push** 两个**同 sha** 的 run，
必须串行才能避免 release job 对同一 tag 并发 delete+create 的竞态。
若改成按 `ref` 分组并开启 `cancel-in-progress`，这两个 run 会并行，反而踩回老坑。

### 3.3 推送侧：改用 Git Data API 单 commit

批量改动改用 Git Data API（blob → tree → commit → update-ref），
**所有文件落在同一个 commit 里**，从源头消除中间态，也只会触发一次 CI。
