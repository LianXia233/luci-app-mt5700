**架构兼容性修复版** —— 解决「固件与软件包架构显示一致却装不上」。

![网络状态页面](https://raw.githubusercontent.com/LianXia233/luci-app-mt5700/main/docs/images/network-status.png)

### 主要修复

- **装不上**：新增 `aarch64_generic` 架构产物。apk 对 `<base>_<variant>` 做严格匹配，iStoreOS 25.x 等固件声明的是 `aarch64_generic`，此前只提供 `aarch64_cortex-a53` 的包，安装必然报 `uninstallable arch`。
- **装完不可用**：postinst 覆盖了 luci.mk 的默认实现，`rpcd reload` 与 LuCI 缓存清理从未执行 —— 页面所有 RPC 调用报 `Access denied`，重启后才正常。
- **模组在线却上不了网**：自动拨号幂等判定原来只比开关、不比拨号方式；接口拉起只有 35 秒窗口且不重试。现为双字段判定 + 退避重试 + 周期对账 + hotplug 兜底。
- **接口不被创建**：接口缺失时原为静默跳过，现检测到模组 USB 网口即按 `proto=dhcp` 自动创建。
- **AT 口探测过窄**：候选从 `ttyUSB*` 扩到 `ttyUSB / ttyACM / ttyAP`，并按 sysfs 接口名判定优先级。
- **构建期防错**：删除按宿主架构兜底推断，新增「矩阵期望架构 == SDK 实际架构」闸门与后端 ELF 架构自检。

完整变更记录见 [CHANGELOG.md](https://github.com/LianXia233/luci-app-mt5700/blob/main/CHANGELOG.md)。
