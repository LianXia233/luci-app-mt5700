# v1.26.0

**主题**：短信模块深度重构。把「逐条 AT 透传、各步之间随时被后台巡检插队、列表来自 localStorage 快照」的旧链路，改为「一次 RPC 一个语义动作、后端单事务独占通道、全部实时回包」。同时随包升级 rustls-webpki 0.103.16（RUSTSEC-2026-0382）。

---

## 1. 为什么要重构

旧短信链路有三类结构性问题：

1. **命令被拆散透传**：发一条短信要在前端/后端之间往返 `AT+CMGF` → `AT+CSCA?` → `AT+CMGS` 多次独立 RPC。每两步之间，后台巡检（信号 `^HCSQ`、缓存刷新、流量统计、自动拨号对账）都可能插进来，把模组上下文打乱——比如刚切到 PDU 模式就被别的命令挤开，后续 `AT+CMGS=<长度>` 的语义就变了。
2. **无优先级概念**：短信命令与后台轮询在 AT 队列里平级竞争，用户正在发短信时后台一个 2s 的状态轮询就能让提交多等好几秒。
3. **列表来自快照**：已读状态、已发记录存 localStorage。模组侧删了短信、换了存储区，界面还在按旧序号操作，`AT+CMGD` 全打在空气上。

## 2. 新调度模型（不新建并行串口通道）

三层机制，全部复用既有单 AT 通道：

| 层 | 机制 | 语义 |
|:--|:--|:--|
| 优先级 | `AtPriority::Sms = 4` | 短信命令排队时优先于一切命令放行；**不打断**正在执行的命令，等它自然结束后下一个放行的就是短信任务 |
| 暂停门 | `SmsMode` 租约 | 进入短信中心登记带 TTL 的租约，期间非短信命令申请通道一律等待（后台轮询插不了队）。租约 300s 封顶，后台 sweep 清扫——前端崩溃 / WS 断开 / 忘记释放都自动失效，不会永久停轮询 |
| 事务锁 | `SmsTransaction` | 长短信分片、批量删除、开关短信功能等多步操作全程持有 `GatePermit`，中间不释放，杜绝其它命令插进事务中间；超时/取消不泄漏许可 |

AT 接收循环与 URC 派发在暂停期间**保持工作**——暂停只挡「发送新命令」，不收 URC。`+CMTI`（新短信到达）反而改走 Sms 最高优先级立即读取，绕过暂停门。

## 3. 无缓存实时语义

- 新增语义化 RPC `method=sms`：`list` / `send` / `delete` / `purge` / `capacity` / `set_storage` / `get_smsc` / `set_smsc` / `power` / `set_ims` / `get_ims` / `session_*`。ucode 侧动作白名单 + 参数逐项取值，不做命令拼接，杜绝 AT 注入。
- 列表/正文/容量/删除结果全部来自模组实时回包；localStorage 快照依赖移除（仅保留旧缓存清理代码）。
- 前端每次操作后回读列表 + 容量；删除按模组真实序号并回读确认。

## 4. 发送链路

- PDU 编解码全部收敛到后端 `pdu.rs`（前端 `smsEncode.js` 删除）：GSM7/UCS2/8bit 自动选择、UDH 长短信分片（8bit/16bit 参考号、septet 边界 fill bits 精确处理）、SCTS 时区四分之一小时有符号解码。已按《MT5700M-CN 功能应用指南》第 5 章核对 `CMGF` / `CMGS` / `CPMS` / `CMGL` / `CMGD` / `CNMI` 全部口径；中文走 UCS2，规避 text 模式「AT 不支持发送中文」的限制。
- 保持单次提交 `AT+CMGS=<TPDU长度>\r<PDU>`（v1.25.2 确立的字节级写法），PDU 以字符串参数直达串口，不经任何转义层。
- **发送结论三档**：Accepted（模组回 `+CMGS: <ref>`）/ Rejected（`+CMS ERROR` / `+CME ERROR`）/ Unknown（超时或无响应）。**结果不明时绝不自动重发**——避免重复计费；前端对 Unknown 给出明确警示而非假成功。同一目标 + 正文 10 秒内去重。
- 超时三层对齐：后端 send 总预算 60s（覆盖长短信全事务）、ucode nc 硬超时 70s、前端 75s——下层必须小于上层，保证先拿到后端结论而不是被中间层先掐断。
