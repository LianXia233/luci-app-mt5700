**Config 解耦与通知精细化版** —— 把集中耦合的 Config 页面拆成模块化的独立配置体系，PC 用右侧抽屉、移动端用底部面板；通知系统具备分类型的独立频率与时段门控，企业微信支持 Markdown 并与 QQ 共享通道限流，短信/来电作为实时事件豁免通道节流。彻底删除已废弃的「批量汇总标题」功能。全部开关默认关闭，升级后行为不变。

### 为什么改

- 原 Config 页面把连接、网络、通知、模板四类配置塞进单个 `service.js`（1501 行），任何一类改动都要碰同一文件，UCI 键读写互相交织、难以独立维护。
- 通知推送缺少执行层的细粒度控制：生产者侧只有信号类限频，短信/来电/存储满没有独立的频率与时段策略，且所有推送共用一条无节流的发送路径。
- 多轮审查（PR #57 / #58 / #59，Codex + 三路人工）发现并修复了频率闸门并发非原子、延迟补发丢失唤醒、抽屉脏标记与回滚、焦点陷阱逃逸等真实缺陷。

### 主要改动

- **重构(config)** `service.js` 从 1501 行收缩为编排层（约 370 行），拆出 `config-common / config-drawer / config-connection / config-network / config-notify / config-templates` 六个独立公共模块；每模块只写自己负责的 UCI 键，公共逻辑（UCI 读写、夹取、时间校验、转义）统一到 `config-common`。作者署名、服务状态与重载/重启入口原样保留。
- **界面(config)** JS 创建真实浮层（非纯 CSS 伪装）：PC 右侧 Drawer / 移动端 Bottom Sheet 共用一套交互；遮罩与外部点击不关闭、ESC 未保存二次确认、焦点锁定与 Tab 循环、滚动锁定、防重复提交、保存失败保留数据；监听 `visualViewport` 防软键盘遮挡，模块资源经 `onClose` 无条件清理。抽屉字段编辑即标记未保存，保存失败后「放弃修改」回滚暂存 UCI（含已落盘场景的同步回滚）。
- **新增(notify)** 四类事件（短信/来电/存储满/信号）各有独立的频率限制（开关/最小间隔）与推送时段（开关/跨零点起止/延迟或丢弃）UCI 项，统一 `notify_limit_*` 前缀；执行层 `NotifyGate` 在投递那一刻按类型裁决，per-kind `last_sent` + 延迟队列。
- **修复(notify)** 频率闸门 check+reserve 合并进同一把 Mutex 临界区（`admit()`），杜绝并发同类事件双重放行；延迟事件 defer 后以 `tokio::sync::Notify` 唤醒扫描循环，修复窗口到了永不补发；延迟补发的出队与裁决同样原子化。
- **新增(notify)** 企业微信支持 `text`（默认）/ `markdown` / `markdown_v2` 三种消息格式（依官方文档 path/99110：markdown 支持标题/加粗/引用/3 色字体，markdown_v2 支持列表/表格/图片），按字节裁剪（text 2048 / markdown 4096）且 UTF-8 边界安全；裸 URL 不再被 markdown 拆坏。
- **性能(notify)** 抽取共享 `ChannelThrottle`，QQ 与企业微信各持一实例、共用 `qq_max_per_minute` 值——一个设置同步约束两通道。短信/来电作为实时事件豁免通道节流保持实时，信号/存储满照常节流。
- **重构(notify)** 第五轮按需求把信号/存储满的窗外默认策略改为丢弃（开启时段后只推送当前时段内产生的消息，不补发陈旧事件）；短信/来电保持实时直发与 defer 默认不受影响。
- **清理(notify)** 彻底删除「批量汇总标题」`notify_tpl_batch`：前端控件、UCI 读写、`config.rs` 字段/常量、`notify.rs` 模板分支与测试；未误删批量 AT 查询（`batch` 方法）。
