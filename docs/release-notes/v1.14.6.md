**Debian 分支 v1.14.6 为模组设置「系统控制」区域重构与高危操作分级确认版**：将 `main` 分支 v1.14.6 的前端改动移植到独立 WebUI。

### 系统控制区域重构

- 「重启模组」与「恢复出厂设置」由平铺按钮改为**分级操作条**（`.mt-sysctl-item`）：
  - 重启 = 警戒级（`is-warn`，琥珀色按钮 + 橙色风险提示）；
  - 恢复出厂 = 危险级（`is-danger`，红色按钮 + 红色风险提示）。
- 每条操作条采用「风险色点 + 标题 + 说明 + 按钮」的横向布局，按钮统一 `min-width: 128px`，两按钮右对齐、尺寸一致。
- 页面内以 `mt-sysctl-*` 作用域注入样式，**不污染全局**，也不影响其他页面既有样式。

### 高危操作分级确认

- **重启模组**：点击后弹出 **1 次**确认（「确认重启」），确认后下发重启命令。
- **恢复出厂设置**：点击后**连续弹出 3 次**警告确认，按钮文案依次为 `继续（1/3）` → `继续（2/3）` → `继续（3/3）`，任一步取消即终止；三次全部确认后才真正下发恢复出厂命令。
- 确认链为纯前端交互逻辑，确认次数与文案按风险等级区分，用户可从任一步安全退出。

### 移植说明

- 改动落在 `webui/luci-static/resources/view/at-webserver/modem_settings.js`，命令下发仍经既有 `send()` 通道；Debian 侧该通道通向 `rpc.js` 的 HTTP API 与后端 AT 队列，**排队、优先级与超时语义不变**。
- 本次改动与传输层解耦：`main` 分支的 `service.js`（systemd 服务重启页）在 Debian 分支是独立实现，其服务重启逻辑走 `/api/service/restart`（后端优雅退出 + systemd `Restart=always` 拉起），**未被本次改动触及**。
