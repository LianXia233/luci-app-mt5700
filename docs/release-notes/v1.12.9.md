**修好了「4G 下 SINR 读不出来」** —— `^HCSQ` 的 LTE 字段顺序解析反了，SINR 被当成 RSRQ 吃掉；连带修掉 4G 下 `^MONSC` 字段整体错位（RSRP/RSRQ 显示乱值）的问题。

### 修复

- **fix(hcsq)**: `^HCSQ` 的 LTE 分支此前按 `<rsrp>,<rsrq>,<sinr>` 解析，而手册 13.5 的字段表是 `<lte_rssi>,<lte_rsrp>,<lte_sinr>,<lte_rsrq>` —— LTE 比 NR 前面多一个 RSSI，**SINR 在 value3、RSRQ 在 value4**（NR 恰好相反）。实测 `^HCSQ: "LTE",45,34,106,19`：
  - 修复前：RSRP -106 dBm / RSRQ -3 dB / SINR -16.2 dB（把 RSRQ 的 19 当成了 SINR）
  - 修复后：RSSI -76 dBm / RSRP -106 dBm / **SINR 1.2 dB** / RSRQ -10 dB
- **fix(monsc)**: 手册 13.9 中 LTE 的 `^MONSC` 布局与 NR 完全不同（无 flag 位、无 SINR，末位是 RSSI，PCI/ARFCN/TAC 为十六进制）。旧实现套 NR 布局，4G 下 RSRP/RSRQ/cid/pci/channel 全部错位（实测 RSRP 显示 -6、RSRQ 显示 -67 这类乱值）。现按制式分派解析。
- **fix(status)**: `^HCSQ?` 不再只在「`^HFREQINFO` 一条载波都没有」时才查。4G 下 `^HFREQINFO` 正常返回 LTE 载波、`^MONSC` 不带 SINR，旧判断让 4G 永远走不到 `^HCSQ`，SINR 恒为「—」；现改为三项有缺就补查，只填空缺不覆盖。
- **fix(hcsq)**: `255`（未知或不可测）不再换算成 -44 dBm / -3 dB 这类假值，一律按「无数据」返回。
- **fix(urc)**: Rust 后端的 `^HCSQ` 分支同样把 RSSI 位当 RSRP，一并按制式取位。
- **fix(sinr)**: 消除 0.2 dB 步进的浮点尾差（不再显示 `25.200000000000003`）。

5G（NR）分支字段顺序本来就与手册一致，本次**行为保持不变**。
