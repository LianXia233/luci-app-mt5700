**缺陷修复版** —— 跟进 v1.31.1 合并后 Codex 复核提出的两条 P2：SCC 信号「匹配到辅小区却没有读数」时缺少可解释原因、传输失败一律被记成「辅站查询超时」；并把 Rust 侧 AT 超时分类贯通到前端，避免模组静默被误报成 AT ERROR。零信任复审另收口两处边界：HFREQINFO 分支的 RSSI 透传、`at` 成功应答的 JSON 形状。

### 主要改动

- **fix(ui) 匹配到小区 ≠ 拿到读数**：新增 `hasUsableSignal()`，判据与渲染层破折号对齐（RSRP / RSRQ / SINR / RSSI 全空即缺测）；HFREQINFO 分支与孤儿 SCC 一并补 `signalReason`，绝不伪造读数、不复制 PCC 值。
- **fix(ui) 保留真实失败原因**：新增 `atStatusFromResult()`，仅 `cause: timeout` 记超时，通道类快速失败（not-connected / circuit-open / not-listening / no-nc / spawn-failed / no-reply）记 `unavailable`，后端明确报错记 `error`；`computeSccSignalReason()` 补齐 `not-queried` / `not-applicable` 口径。
- **fix(at) cause 贯通三层**：`AtCommandResponse` 新增 `cause: Option<String>`；外层应答预算耗尽直接标 `timeout`，`at_failure_cause()` 把排队预算耗尽与连接超时归类为 `timeout`，模组明确回 ERROR 保持 `None`；`at` 出口把 `cause` 回传，ucode 原样透传、`rpc.js` 转发，前端因此能真正区分超时与后端报错。
- **fix(ui) 补齐 RSSI 透传**：`Parse.carrierSignalFor()` 对 LTE 命中返回 `rssi`，但 HFREQINFO 分支此前未放进载波对象；「仅上报 RSSI」的 LTE SCC 虽被判为有读数，渲染层第三列仍是一排「—」且无解释。现补上 `rssi` 透传，并让 `sigReasonText` 判据覆盖 `rssi`。
- **fix(at) 成功应答形状不变**：`at` 出口原用 `json!` 无条件拼 `cause`，`skip_serializing_if` 对 `json!` 不生效，成功应答也会多出 `cause:null`；改为仅在 `Some(cause)` 时写入该键。
- **ci** `checks.yml` 新增 `Rust 单元测试` job（`cargo test --locked`，15 分钟超时），补齐 CI 原先只跑 Node、不编译 Rust 的门禁缺口。
