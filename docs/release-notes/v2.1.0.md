# v2.1.0 — NTP 时间源 + 日志大小封顶 + 全局时间统一

**v2.1.0 为 `main` 分支 v1.24.x 能力的 Debian 移植版**：新增 NTP 优先的全局时间源
`nettime.rs`、日志文件大小封顶与内存环形缓存 `ringlog.rs`，并把全后端散落的墙上时钟
统一收口到 `nettime`。移植时按 Debian 环境调整时区实现（直接用 `chrono::Local`），
其余行为与 `main` 保持一致。

### 背景

- **两条时间线**：此前各模块各自调用 `SystemTime::now()` / `chrono::Utc::now()`，
  日志、通知、定时任务、短信时间戳各读各的，一旦任一来源校正就互相矛盾。
- **日志无限增长**：通知日志（默认 `/tmp/at-notifications.log`）纯 append、无上限，
  长时间运行可写满 `/tmp`（tmpfs 即吃内存）。
- **内存日志无界**：`logger.rs` 的内存缓冲只按条数粗放增长，一条超长 URC / 短信
  正文即可显著撑大常驻内存。
- **时间不可信**：设备时钟可能未校准（无 RTC 电池 / 刚上线 NTP 未同步），
  需要能主动从 NTP 取时并本地维持。

### 新增模块

- **feat(nettime)** `src/rust/src/nettime.rs`：全进程唯一墙上时钟入口。
  - 服务器列表固定为 `ntp.tencent.com` → `ntp.aliyun.com` → `time.cloudflare.com`
    （NTPv4 / UDP 123，单服务器超时 3 秒，取到即止）；
  - 取到后记录「NTP − 设备时钟」偏移，之后**本地计时**，每 **20 分钟**再同步一次，
    不随每次读取同步；
  - 失败按 **3 秒 ×10 次 → 1 分钟 ×10 次 → 20 分钟** 三级退避重试，任何一次
    成功清零连续失败计数；
  - 偏移仅作用于「当前时刻」的计算，设备原始时钟读取不受污染，不会自激累积；
  - NTP 时间戳带 2036 纪元回绕处理，并对落在 [2000-01-01, 2100-01-00) 之外的
    结果按不可信拒绝，防止 DNS 劫持/错误响应灌入离谱时间。
- **feat(ringlog)** `src/rust/src/ringlog.rs`：日志容器与封顶写入。
  - 内存环形缓存**双上限**：条数 1200 + 总字节 512 KiB 同时生效（只限条数不够，
    一条超长正文照样能撑大内存）；
  - 文件封顶写入 `append_capped`：超过上限（默认 256 KiB）时先按**行边界**
    裁掉最旧的一半再追加，绝不切出半行；
  - 序列化结构 `seq/ts/level/msg` 不变，WebUI 无需适配。

### 与 main 分支的差异（时区实现）

- **note(nettime) 时区仍读设备**：`main` 跑在 OpenWrt 上**没有 tzdata**，需要自己
  解析 POSIX TZ 串；**Debian 自带 tzdata**，本分支的 `Tz` 直接就是
  `chrono::Local`（读 `/etc/localtime` + `TZ` 环境变量），NTP 只负责校正 UTC 时刻
  —— 两者正交，不重复实现一套时区解析。

### 全局时间统一（refactor(time)）

以下模块的墙上时钟调用全部改为 `nettime`，消除「日志一个时间、通知另一个时间」
的两条时间线：

- `logger.rs`：日志时间戳；
- `async_runtime.rs`：任务创建时间；
- `pdu.rs`：短信 PDU 时间兜底；
- `notify.rs` / `urc.rs`：通知与 URC 时间；
- `schedule.rs`：定时锁频；
- `httpserver.rs`：HTTP 日志兜底时间戳。

### 间隔测量改用单调时钟

- **fix(atclient)**：「长命令结束于何时」原本用 `SystemTime`（墙上时间）算差值，
  NTP 校正会让差值失真；改为基于 `Instant` 的进程单调毫秒 `mono_ms()`
  （模块级函数，避免实例方法内联问题）。

### 配置

- **note(config)** `debian/config.json` 新增 `log_file_max_bytes`（默认 `262144`，
  小于 4096 的取值回落默认）。

### CI

- **ci(debian) 陈旧提交跳过**：与 `main` 分支 v1.24.3 同款修复 —— build job 先用
  `git ls-remote` 比对分支 HEAD，非最新提交则跳过依赖安装 / 构建 / 校验 / 打包 /
  归档；release job 同步跳过（构建被跳过时无产物可发）。tag 推送与手动 dispatch
  不受影响。并发策略仍按 `github.sha` 分组且 `cancel-in-progress: false`
  （一次发布会同时产生分支 push 与 tag push 两个同 sha 的 run，必须串行避免
  Release 竞态）。

### 影响范围

- 新增 2 个源文件（`nettime.rs` / `ringlog.rs`），改造 6 个既有源文件的时间读取
  与 1 个间隔测量，配置与工作流各一处；WebUI、AT 命令流、业务功能零改动。
