**QQ 机器人扫码绑定** —— 手机 QQ 扫一次码即可取回 AppID / AppSecret 并绑定 openid，替代「去开放平台抄凭据 → 再给机器人发一条消息」的两步流程；同时修掉联调中在真机上暴露的 8 个缺陷，其中一个是会让新密钥当场失效的 P0。

### 为什么改

- 旧流程要求先在开放平台后台抄 AppID/AppSecret 到手填输入框，再给机器人发消息抓 openid。两步都容易出错：抄错一位就鉴权失败，群聊场景还不一定拿得到正确的目标 ID。
- 官方 `@tencent-connect/qqbot-connector` 提供扫码授权：QQ 把「AppID + 加密后的 AppSecret + 扫码者 openid」写进服务端任务，第三方轮询取回。本项目把它落到常驻后端里，一次扫码把三件事办完。

### 主要改动

- **feat(qq)** 新增 `src/rust/src/qqqr.rs`：建任务（32 字节随机密钥）→ 出码（官方 `connect.html`，含 `_wv=2`）→ 2s 轮询 → AES-256-GCM 本地解密（`IV(12)‖CT‖TAG(16)`）→ 直写 UCI → 热替换通道，无需重启服务。请求地址、字段、状态码（0/1/2/3）与超时逐项对齐 SDK 1.2.0。
- **feat(luci)** 新增 `qqqbind.js`：canvas 逐格绘制（不下发 SVG，无注入面）、静区 4 模块、按位图实际像素设宽避免非整数缩放、二维码与可点击链接双兜底、过期自动换码、关闭面板即取消。
- **security** AppSecret 只存在于后端内存与 UCI，前端只拿 AppID 与 openid；写入后配置文件收紧为 `0600`；RPC 错误串对 argv 统一脱敏（原实现会把 `qq_app_secret=<明文>` 带回浏览器）。
- **fix(P0)** 保存表单会把刚扫码拿到的密钥覆盖成页面旧值（首次绑定是空串），且保存会触发 procd 重启 —— 结合 `qrBound` / `qqSecretDirty` 门控，只写用户真正改动的键。
- **fix(P1)** 状态机区分「终态失败」与「可重试的网络错误」；并发 `start` 串行化并用会话代号复核，重复出码不再产生死码；落盘失败不再热替换通道；`openid` 为空时不清空既有目标。
- **fix(P1)** 弱网重试：轮询改为指数退避（2→4→8→15s 封顶，约 89s 预算），不再固定 6 秒放弃；`qq_qr_poll` 的 RPC 预算与后端 10s HTTP 对齐。
- **fix(luci)** 兼容 LuCI 26.x 的类式模块工厂（模块必须返回 Class 子类，否则整页 `require` 抛 `factory yields invalid constructor`）；保存不再把 rpcd 的 `NO_DATA` 当成失败；放弃修改确认条滚入视野。
- **fix(init)** `reload` 现在能杀掉「二进制已被替换」的旧进程：`/proc/<pid>/exe` 会变成 `… (deleted)`，与 `$PROG` 精确比较导致漏杀，升级后一直跑旧二进制。
- **perf** HTTP 连接复用（`ureq::Agent` + keep-alive），2s 一次的轮询不再每轮做一次 TLS 握手。
- **test** 新增 `tests/luci-module-class-test.js`，把 LuCI 模块工厂契约固化为门禁；`qqqr` 新增 4 个单测（终态失败、会话代号复核、数值容错、密钥脱敏）。
- **chore** 版本 2.0.2 → 2.1.0（新增功能走 minor）。

### 升级提示

- 覆盖安装后请按 `Ctrl + F5` 强刷：`MT5700_UI_VERSION` 与模块缓存整体失效，否则可能仍加载旧的 `rpc.js` / `config-notify.js`。
- 已有手填 AppID/AppSecret 的配置完全兼容，扫码只是新增入口；原有的 `qqbind`（发消息抓 openid）流程保留。
- 扫码绑定会把凭据写入 `/etc/config/mt5700d`（权限 600）；若需要凭据完全不落盘，仍可用环境变量 `QQ_BOT_APP_SECRET` 注入。
