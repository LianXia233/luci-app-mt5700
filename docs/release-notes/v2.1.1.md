**时间口径收敛与夜间模式可读性** —— 前端业务时间不再取浏览器时钟，一律消费后端 `nettime` 的权威时刻；同时修掉「半套暗色规则」造成的夜间小字看不清。协议向后兼容，老前端忽略 `at_ms` 即可。

### 为什么改

- 插件早就有唯一时间源：后端 `crate::nettime`（NTP 优先，取不到回退设备时钟）。但前端有 4 处业务时间还在用浏览器时钟：趋势图横轴、终端命令历史、`^REJINFO` 上报打戳与拒绝卡片。手机时区设错或系统时间偏了，这些时刻就和日志、通知对不上——排障时最需要对齐的时刻反而最不可信。
- 夜间模式则是「半套暗色规则」：logcat 分类徽章有完整 21 条 `.at-dark` 提亮，但日志级别 / 方向 / 来源徽章与两处视图的局部样式漏写，10~11px 小字在深底上对比度只有约 2~3:1。

### 主要改动

- **fix(backend)** `at` RPC 应答与 `raw_data` URC 上报注入 `at_ms`（`nettime::now_ms()`），前端据此打业务时间；`data` 仍是纯文本，老前端忽略新字段即可。
- **feat(luci)** 新增 `Mt5700d.serverClock(atMs[, withDate])`：只格式化后端给的 epoch，无有效值返回 `null` 由调用方显示占位，**不回退**浏览器时钟。趋势图横轴、终端命令历史、REJINFO 打戳与卡片展示 4 处改用该出口。
- **fix(luci)** 失败应答与批量路径同样透传 `at_ms`：`sendCommand` 失败分支、`sendBatch` 逐条、status 页预取缓存的成功/失败两个分支。批量是 status 页取数主干，漏这一处会让 `hfreq.at_ms` 恒为 `null`，横轴永远停在「—1」「—2」占位——等于修复在正常路径上没生效。
- **fix(css)** 补齐 `loglv` / `logdir` / `logsrc` / `logscroll-btn` 等徽章的 `.at-dark` 提亮；`--mt5700-text-muted` 暗色值 `#64748b` → `#8fa3b8`（暗底对比度约 3.6:1 → 6.6:1）；模组设置页、拨号页局部样式补 `html.at-dark` 分支；信号档位标签不透明度 `0.5` → `0.85`。
- **fix(css)** `MT5700_CSS_VERSION` 2.46.9 → 2.46.10。`uhttpd` 对静态资源恒给 `Last-Modified: 1970`，失效只能靠 `?v=`；不递增就是「代码已改、界面未变」，夜间修复发不出去。
- **test** 新增 `tests/server-time-test.js`（24 项）：锁定后端 `at_ms` 注入、前端透传链（含失败应答与批量/预取）、4 处违规点禁用浏览器时钟，并对 `serverClock` 做纯函数行为断言；`global-css-test.js` 第 7 节逐个断言徽章暗色规则成对出现。
- **docs** `AGENTS.md` 新增第七章「时间口径规则」：唯一墙上时间入口、三类时间（墙上/间隔/纯技术）强制分流、禁止回退的反例表、以及「`serverClock` 时区取浏览器本地，只解决时钟偏差不解决时区设错」的已知局限。
- **ci** `checks.yml` 的 Rust 作业显示名由「Rust 单元测试与 Clippy」改回「Rust 单元测试」，与 `main` 分支保护要求的必需检查 context 对齐。此前名称不一致，必需检查永远不出现，PR 恒为 `blocked` —— 四项 CI 全绿也合不了，且状态只报 `blocked` 不报缺哪条。Clippy 仍在该作业内执行。
- **chore** 版本 2.1.0 → 2.1.1。

### 升级提示

- 覆盖安装后请按 `Ctrl + F5` 强刷：`MT5700_UI_VERSION` 与 `MT5700_CSS_VERSION` 同时递增，模块与样式表缓存整体失效。

- 协议只增字段不改形状，新后端配老前端完全兼容。
