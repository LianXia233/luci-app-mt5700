**Debian 分支新增 GitHub Actions 云编译，产出 `.deb` 二进制包**：在原有源码安装方式之外，提供标准 Debian 包分发路径。

### 云编译工作流（`.github/workflows/build-deb.yml`）

- **架构矩阵**：两架构均使用 GitHub 官方**原生** runner ——
  `amd64` = `ubuntu-24.04`，`arm64` = `ubuntu-24.04-arm`（Cobalt 100 / Arm Neoverse N2，4 vCPU）。
- **arm64 为何改用原生 arm runner**（而非 x64 交叉编译）：
  1. 无需安装 `gcc-aarch64-linux-gnu`、无需注入 linker 与 `AR` 环境变量，
     配置面更小、失败点更少；
  2. 产物由 arm64 原生工具链产出，不经交叉翻译层，可信度与兼容性更佳；
  3. `ring`（`ureq`/rustls 的 TLS 后端）需要 C 编译器与汇编器，原生 runner 自带 gcc，
     天然满足（交叉场景下必须显式安装交叉工具链，否则链接失败）。
- **前置条件：仓库必须为 public。** GitHub 的 `ubuntu-*-arm` 免费标签仅对公开仓库开放；
  仓库转为 private 后该标签不被调度，workflow 直接失败而不会静默降级。
- **新增 runner 架构闸门**：构建步骤显式校验 `uname -m` 与目标架构是否匹配
  （`amd64:x86_64` / `arm64:aarch64`），不匹配即`exit 1`；产物校验步骤再断言
  ELF `Machine` 与目标架构一致，防止误配静默产出错包。
- **触发条件**：`push` 到 `Debian` 分支、打 `debian-v*` 标签、或 `workflow_dispatch`
  手动触发（可指定 deb 修订号）。
- **标签空间隔离**：本分支 Release 标签统一用 `debian-v*` 前缀，与 `main` 分支的 `v*`
  （OpenWrt ipk/apk）完全隔离，避免同名 Release 冲突与工作流误触发。
- **并发控制**：按 `github.sha` 归组串行（`cancel-in-progress: false`），消除分支推送与
  标签推送指向同一 sha 时两个 run 并发 `delete + create` 同一 Release 的竞争。
- **步骤细分与汉化**：编译 job 9 步（检出代码 / 环境准备 / 依赖安装 / 构建执行 /
  产物校验·二进制 / 打包执行 / 产物校验·deb 闸门 / 日志归档 / 产物归档），
  发布 job 7 步（检出 / 下载 / 汇总校验 / 版本号判定 / 生成说明 / 发布 / 结果校验）。
- **构建日志归档**：推送至 `ci-logs` 分支的 `logs/debian/` 目录，按架构与时间命名
  （`.txt` 扩展名，规避仓库 `.gitignore` 的 `*.log` 规则）。

### 打包脚本（`debian/build-deb.sh`）

CI 与本地共用同一脚本，避免两套逻辑漂移。三项关键设计：

1. **版本单一来源**：取自 `src/rust/Cargo.toml` 的 `version`（后端即包本体），Debian 修订号
   由 `--revision` 指定（默认 `1`），产物为 `<upstream>-<revision>`。杜绝「包版本与二进制
   版本不一致」这类难排查的问题。
2. **架构自 ELF 判定**：从产物读取 ELF `Machine` 字段判定架构，**不信任**
   `dpkg --print-architecture`。交叉编译场景下后者返回宿主架构 —— 在 x86_64 机器上会产出
   `Architecture: amd64` 却内含 aarch64 二进制的坏包，该包在 arm64 设备上会被 dpkg 直接拒绝
   （`package architecture (amd64) does not match system (arm64)`）。这是本次开发中实测
   发现并修复的缺陷。CI 改为原生 arm runner 后宿主与目标架构天然一致，但本脚本仍保留自 ELF
   判定，以支撑本地交叉编译等场景。
3. **依赖动态推导**：读 `objdump -p` 的 `NEEDED` 条目映射为 Debian 包名并**按首次出现顺序
   去重**（`libc.so.6`/`libm.so.6`/`libpthread.so.0` 均映射到 `libc6`，不去重会产生
   `Depends: libc6, libgcc-s1, libc6` 的 lint 告警）。未识别的库会告警提示补充映射，
   不静默丢弃。

### 包内容布局

| 路径 | 权限 | 说明 |
| --- | --- | --- |
| `/usr/bin/at-webserver` | 0755 | 后端二进制 |
| `/usr/share/mt5700/webui/**` | 0644/0755 | WebUI 静态资源（含 `_layout-test/`） |
| `/etc/mt5700/config.json` | 0644 | 主配置，**conffile**（升级保留用户修改） |
| `/etc/mt5700/on-uplink.sh` | 0755 | 拨号就绪钩子 |
| `/lib/systemd/system/at-webserver.service` | 0644 | systemd 单元 |
| `/usr/share/doc/at-webserver/` | 0644 | README、README.Debian、LICENSE |

`DEBIAN/` 元数据：`control`（含 `Depends`/`Installed-Size`/`Section`/`Homepage`）、
`conffiles`、`postinst`、`prerm`、`postrm`。

- `postinst` 遵循 `deb-systemd-helper` 惯例；**服务启动失败不中断安装**（未接模组时属预期），
  仅打印日志提示，待模组接入后 `systemctl restart at-webserver` 即可。
- `prerm` 停服并禁用；`postrm` 重载 systemd 运行时。

### 实测验证（Debian 13 / x86_64）

- 编译：amd64 原生 1m12s；arm64 交叉 1m00s（Rust 1.99.0）
- 架构一致性交叉校验：`control` 声明与包内二进制实际架构**两架构均一致**
- 生命周期：安装 → 用户改 `config.json` → 重装（**conffile 保留用户修改**）→
  `dpkg -P` purge（全部路径清除，dpkg 记录清空）
- 功能抽检：包内启动后 `/`、`/luci.js`、`/app.js`、`mt5700.css`、`network_status.js`、
  `service.js`、`/_layout-test/status-mock.html` 均 HTTP 200；`/api/service/status`
  正常返回；v1.14.5 英雄区紧凑化样式确认在包内
- 元数据闸门：5 项关键路径存在性 + WebUI 文件数（32）全部通过
