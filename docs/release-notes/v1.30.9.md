# v1.30.9 发布说明 — 定时锁频编排页重排（状态指标化 / 参数双列 / 时段分卡 / 输入框不预填）

本次只改「定时锁频编排」页的排版与控件，不改任何下发内容：`AT+SCHED=` 的 JSON 结构、`AT+SCHED?` 的解析、UCI 键名全部保持原样。

## 问题

### 1. 输入框里会冒出并不存在的值

原实现这样写两个数字框：

```js
var checkIntervalInput = Mt5700.input('number', '10', String(draft.check_interval));
var timeoutInput      = Mt5700.input('number', '30', String(draft.timeout));
```

`Mt5700.input(type, placeholder, value)` 的第三个参数只要 `!= null` 就会被赋值。当 `AT+SCHED?` 没返回这两个字段时，`draft.check_interval` 是 `undefined`，`String(undefined)` 得到字面量 `"undefined"`，于是输入框里显示的就是 `undefined`。

同类问题在夜间起止时间上换了个形态：`p.start || '22:00'` 会在后端没给值时凭空填一个 22:00。用户看到的值既不是自己填的、也未必是后端存的，属于「界面对配置的伪造」。

### 2. 一页塞一张卡，字段一行一个

所有内容都在同一个 `.mt5700-card` 里：四个数字/开关、两张时段表、每段两套锁频表，全部单列往下堆。桌面端右侧大片留白，手机上要滚很久才见得到保存按钮。

### 3. 锁频条目只有 placeholder，没有字段标签

```html
<select 频段> <input placeholder="频点"> <select 自动> <input placeholder="PCI"> [删除]
```

一行里塞 4 个控件、靠 placeholder 说明含义，placeholder 一消失就分不清哪格是频点哪格是 PCI。而且不管什么锁频类型，这 4 个控件全都显示 —— 类型 3（锁 Band）根本不带频点，类型 1（锁频点）不带 PCI，填了也会被 `toLockLists` 丢弃，用户却以为自己配置生效了。

### 4. 开关没有状态文字

页面内自写了一份裸 checkbox（`mkCheck`），`ui.js` 里其实已经有带「模组拒绝则回滚勾选」约定的 `Ui.switch`。拨杆开与关只有颜色差异，连排四个开关时很难一眼确认当前值。

## 修复

### 输入框不预填

统一收口到两个小工具：

```js
// 后端没给值就留空，绝不把 undefined / 臆造的默认值写进输入框
function raw(v) { return (v == null || v === '') ? '' : String(v); }
function toNum(v) { /* '' 与非法值 → null，而不是 0 */ }
```

- `check_interval` / `timeout`：`raw(draft.check_interval)`，只有后端真返回数字才回填；
- 夜间起止时间：`raw(p.start)`，去掉 `|| '22:00'` 的兜底；
- 空白时用 placeholder 说明期望（`10 - 3600`、`如 22:00`），示例不再伪装成值；
- 保存时对空值给明确文案，而不是静默按默认值下发。

`toNum` 与 `Number()` 的差别是要点：`Number('')` 是 `0`，会让「空」被当成「填了 0」。

### 排版

| 区块 | 原来 | 现在 |
|:--|:--|:--|
| 运行状态 | 一条 `mt5700-inline` 串起「当前时段：X 下次切换：Y 已切换 N 次」 | 四格 `.mt5700-metrics` 指标卡；`applied=false` / 无 status 各自单独一行提示 |
| 调度参数 | 5 个字段单列 | `.mt5700-form-grid` 双列；窄屏单列，手机端标签居左 |
| 夜间 / 日间 | 同一张卡里上下排，用 `.mt5700-modal-title` 当小标题（借用模态框样式） | 两张并排卡片（`.mt5700-grid-2`），卡内按「启用 → 时段 → 4G → 5G」分段，分段标题自带色条 |
| 锁频条目 | flex 换行，无标签 | 「序号 + 字段网格 + 删除」三列，每个控件带 `label`；删除按钮钉在行顶 |
| 展开 / 收起 | 首屏只有一个「展开配置」按钮 | 去掉折叠，进入即可编辑 |

### 按类型裁剪字段

| 锁频类型 | 展示的字段 | 依据 |
|:--|:--|:--|
| 0 关闭 | 无（一行说明） | `toLockLists` 直接返回空 |
| 1 锁定频点 | 频段 / 频点 /（NR）SCS | 手册 13.12.1 / 13.13.1 只带 band、arfcn、scs |
| 2 锁定小区 | 频段 / 频点 /（NR）SCS / PCI | 同上，追加 pci |
| 3 锁定 Band | 频段 | 只下发 band 列表 |

字段数为奇数时最后一格占满整行，避免两列栅格右侧空出一格。

### 实时下发预览

每个锁频块底部加一行等宽字体的预览：

```
将下发：band=78,41 · arfcn=630000,520000 · scs=1,1
```

由 `Parse.toLockLists` 现算，未填全时转成「待补全：请至少输入一个有效的 NR 频段」。这样「填了什么」与「要下发什么」在保存前就能对上。

### 开关

全部改走 `Ui.switch`，并在拨杆右侧补一个状态文字（`已开启` / `已停用`，颜色跟随主题 `success` / `muted`）。停用某个时段时，该时段的配置区整体压暗（`opacity: .45` + `pointer-events: none`）并显示说明，开关本身仍可点击恢复 —— 配置不丢，只是不参与调度。

### 轮询不再重建表单

原实现每次 15 秒轮询都会 `render()` → 重建表单，正在输入的焦点会被夺走。改为：轮询只“重画状态卡”，表单仅在首次加载、保存成功、或用户点「放弃修改并重载」时重建。要覆盖草稿必须显式操作，不会被后台 GET 悄悄顶掉。

## 实现细节：为什么新增类而不是改通用类

`mt5700.css` 是全插件共用的，改 `.mt5700-input` / `.mt5700-lock-item` 会波及其它十余个页面。因此本次只在文件末尾追加一组仅本页使用的类：

- `.mt5700-switch-row` / `.mt5700-switch-state` —— 开关行与状态文字
- `.mt5700-sched-time` / `.mt5700-sched-time-sep` —— 起止时间行
- `.mt5700-sched-sub` / `.mt5700-sched-sub-title` —— 4G / 5G 分段标题
- `.mt5700-lock-row` / `.mt5700-lock-row-index` / `.mt5700-lock-fields` —— 锁频条目
- `.mt5700-sched-note` / `.mt5700-sched-preview` / `.mt5700-sched-detail.is-off` —— 说明、预览、停用态

样式版本 `MT5700_CSS_VERSION` 2.43.0 → 2.44.0。uhttpd 给静态资源的 `Last-Modified` 恒为 1970，浏览器会长期复用旧 CSS，不换版本号用户刷新也看不到新样式。

## 追加：定时任务彻底脱离前端

### 问题

调度逻辑本来就在 Rust 守护进程里（`Scheduler::run`），与浏览器无关，但有两处会让「关掉页面后不像在正常工作」：

1. **唤醒节奏只按检测间隔**。`run()` 每 `check_interval` 秒醒一次，间隔设成 1800 秒时，22:00 的切换最多要等到 22:30 才下发。用户看到的现象是「时间到了没切」，而日志里其实什么错都没有。
2. **模组重连后锁频丢失却不会补**。`connected_flag` 只有真/假两态，USB 重新枚举、模组自复位之后链路又变成 true，调度器认为「已下发」而跳过 —— 夜里锁着的 B8 在模组重启后就一直不锁。

### 修复

| 位置 | 改动 |
|:--|:--|
| `Scheduler::run` | 睡「检测间隔」与「距下一个切换点」的较小值，到点后 1 秒内判定；切换点之后继续按检测间隔做无服务巡检 |
| `Scheduler::note_reconnect` | 每轮读取 `AtClient::connect_epoch()`（每次成功建链 +1），代次变化即把 `applied` 置回 false，本轮 tick 自动补下发 |
| `REAPPLY_AFTER_RECONNECT_QUIET` | 刚下发过 120 秒内不补，避免链路抖动引发 `CFUN=0/1` + 锁频的反复切换 |
| `schedconfig::seconds_to_next_switch` | 新增：返回距下一个时段端点的秒数，`next_switch_at` / `next_switch_time` 都由它推导，边界口径只有一处 |

页面关掉、手机断网、没人登录，只要守护进程在跑，到点就切 —— 这条现在有单元测试盯着边界计算（跨零点、正好在端点那一分钟、端点非法）。

## 追加：时间口径统一到插件自己的时间源

插件内「现在几点」只有两个出口：`localtime`（时区）+ `nettime`（NTP 优先、失败回退设备时钟）。本次把调度链路上剩余的分支全部收敛过去：

- `status()` 里 `next_switch` / `next_switch_time` / `server_time` 取**同一个** `nettime::now()`，不再各取一次（分别取会差几秒，用户拿它们互相对时间就会觉得对不上）；
- 新增 `next_switch_time`（`YYYY-MM-DD HH:MM`）与 `next_switch_in`（秒）：只给 `HH:MM` 时，22:00 与「明天 06:00」在页面上长得一样；
- 页面不再用浏览器时钟做任何推算，只回显后端给的时间与倒计时，并标注「插件时间」；
- `next_switch` 的边界计算从「分钟粒度比较」改为「秒粒度差值」，`22:00:30` 不会再被当成「22:00 已过」。

## 追加：Codex 评审 P2 —— ARFCN / PCI 取 0 被丢弃

`Parse.toLockLists` 原来写的是 `String(i.arfcn || '')`。`0` 是合法值（LTE band 1 的最低 EARFCN 就是 0，PCI 0 也是真实小区），却被 `||` 判成空，于是用户明明填了 0，保存时却提示「频点必须为 0-4294967295 的整数」。

改为只把 `null` / `undefined` 当空：

```js
var cellText = function (v) { return v == null ? '' : String(v).trim(); };
var arfcns = valid.map(function (i) { return checkArfcn(label, cellText(i.arfcn)); }).join(',');
var pcis   = valid.map(function (i) { return checkPci(kind, cellText(i.pci)); }).join(',');
```

`tests/parse-regression-test.js` 增加三条用例：ARFCN=0 保留、NR 的 ARFCN/SCS/PCI 同时为 0 保留、真的留空仍然报错。

## 追加：全局弹窗文字可见性（不动版式）

实机截图里弹窗标题够深、正文却是浅灰，叠在毛玻璃底上几乎看不清。「取消」键是浅靛蓝，对比也只有 2:1 左右。

根因是正文颜色走主题的 secondary 文本变量，主题（Argon 一类）把它设成浅灰时，插件后面那句 `#475569` 的兜底因为特异性不够压不住。

## 追加：「后端未就绪」提示条不再挤压页面

### 现象

后端不可用（守护进程刚重启、AT 端口被占）时，页面顶部会插一条「模组后端未就绪」提示。它插的是 LuCI 原生 `.alert-message`，属于文档流元素 —— 出现时把整页内容整体推下去，消失时又弹回来。探活抖动一次就跳一次，用户正在填表时输入框会跟着上下移动；再加上 `.mt5700-page` 的 `gap` 与 `.alert-message` 自带的外边距叠加，顶部还会多出一段不自然的空白。

实测（1280×900，顶部 56px 吸顶头部）：

| 场景 | 英雄区 top | 卡片 top |
|:--|--:|--:|
| 改动前 · 有提示条 | 150 | 292 |
| 改动前 · 提示条移除 | 72 | 214 |
| 改动后 · 有提示条 | **72** | **214** |
| 改动后 · 提示条移除 | 72 | 214 |

也就是说：改完之后，提示条出现或消失，正文一像素都不动。

### 做法

| 位置 | 改动 |
|:--|:--|
| `at.css` | 新增 `.mt5700-float-notice`：`position: fixed` 脱离文档流，居中、`width: min(720px, calc(100vw - 24px))`、毛玻璃底 + 阴影、`z-index: 9000`（压在插件弹窗 9400 与 toast 10000 之下）；移动端全宽、字号降一档；`prefers-reduced-motion` 下取消入场动画 |
| `ui.js` `placeNotice()` | 插入时实测「贴顶 + 够宽 + 不占半屏」的头部元素，把 `top` 写成 `头部底边 + 12px`。提示条挂在 `#maincontent`（`z-index:1`）里，主题的固定头部层级更高，不偏移就会被整个盖住 —— 那比挤压更糟 |
| `ui.js` `degradedNotice()` | 提示条加 `role="status"` / `aria-live`；补「×」关闭按钮（只收起本次提示，下次降级重新出现）；窗口尺寸变化时重新测量（横竖屏切换、侧栏折叠） |

关键取舍：**不预留占位**。常见做法是给页面加 `padding-top` 把提示条的位置让出来，但那等于换一种方式挤压 —— 内容照样要下移。悬浮就是「不参与布局」，代价是短暂覆盖卡片顶部的一小块，而后端不可用时那块内容本来也是空的。

### 验证

- 无头浏览器实测四组数据（见上表）：有/无提示条时英雄区与卡片 `top` 完全一致，`document.scrollHeight` 不变；
- 直接跑 `ui.js` 里的 `placeNotice()` 源码：56px 吸顶头部 → `top=69px`；头部不吸顶 → `top=12px`；旁边存在 `#mainmenu`（fixed、贴左不满宽）时不被误判；
- 桌面 / 400px 手机 / 暗色三组截图核对文案换行与关闭按钮位置，无横向滚动；
- `static-check` 4/4、12 个前端单测全通过。

## 追加：弹窗与提示条必须是全局的 —— 抽成 global.css

### 问题：两个「全局组件」写在了两个不同的文件里

上一版把弹窗可读性写进 `mt5700.css`、把提示条写进 `at.css`。插件当时有两个样式入口：

| 入口 | 由谁注入 | 覆盖页面 |
|:--|:--|--:|
| `mt5700.css` | `mt5700.js` —— 视图骨架，12 个视图全部依赖 | **12 / 12** |
| `at.css` | `ui.js` —— 公共组件库，按需引入 | 11 / 12（`service.js` 只 `require mt5700`） |

也就是说弹窗那一段碰巧是全局的，提示条那一段不是。在 `service.js`（服务配置页）上，同一个提示条退回 LuCI 原生横条：

![global css 覆盖对比](../images/global-css-compare.png)

| 指标 | service 页（只有 mt5700.css） | service 页（+ global.css） | 常规页（at + mt5700 + global） |
|:--|:--|:--|:--|
| `position` | `static` | **`fixed`** | **`fixed`** |
| 宽度 | 1244px（撑满内容区） | **720px** | **720px** |
| 圆角 / 阴影 | 3px / `none` | **12px / 有** | **12px / 有** |
| 弹窗正文色 | `rgb(127,127,139)` | **`rgb(51,60,75)`** | **`rgb(51,60,75)`** |
| 正文对比度 | 3.95 : 1 | **11.12 : 1** | **11.12 : 1** |
| 横向溢出 | 0 | 0 | 0 |

`static` 那一列不只是「丑」：它在文档流里，出现时会把整页内容推下去 44px —— 正是上一版要修掉的那个抖动，只是换了个页面复发。

### 做法

| 位置 | 改动 |
|:--|:--|
| `global.css`（新增） | 「弹窗文字可见性」+「后端未就绪提示条」两段整体迁入；顶部注释写清它为什么存在、归谁管。挂在 `mt5700.js`（视图骨架）而不是 `ui.js`（可选组件库）上 —— 全局样式的归属不该取决于某个页面「有没有顺便 require 了 ui」 |
| `mt5700.js` | `MT5700_CSS_VERSION` 2.45.0 → **2.46.0**，新增 `GLOBAL_CSS_VERSION` 1.0.0；先注入 `mt5700.css`、再注入 `global.css`，后者作为最终修订层，同特异性规则上胜出 |
| `mt5700.css` | 移除末尾弹窗段（−95 行） |
| `at.css` | 移除提示条段（−75 行），只留一行指路注释；`AT_CSS_VERSION` 1.14.0 → **1.15.0** |
| `ui.js` | 注释说明提示条样式不再随本文件注入，避免以后又往回加 |
| `service.js` | 补 `require at-webserver/ui` + `Ui.startup(page, null)`：本页数据全走 ubus，`onReady` 无需回调，但探活与提示条必须与其他页同源 |
| `tests/global-css-test.js`（新增） | 29 项回归：依赖可达性、注入顺序、选择器存在性、「只改颜色」约束、两处旧文件不再重复定义 |

变量链是这次唯一需要小心的地方。提示条底色写成：

```css
background: var(--at-bg-glass, var(--mt5700-glass-bg, rgba(255, 255, 255, 0.86))) !important;
```

常规页有 `--at-bg-glass`（`.78`），取到的值与此前**逐像素一致**；`service.js` 没有 at 变量，回落到 `--mt5700-glass-bg`（`.70`）。两边都不会掉成透明，也不需要为某一类页面写第二份规则。
